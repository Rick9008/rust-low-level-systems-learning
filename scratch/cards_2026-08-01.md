## 四、追問 Q&A 沉澱(路上/晚上可複讀)

- **為何不直接 conflation slot?** 資料語意未問清前不能自選——conflation 合約=只有最新值有意義;queue 合約=每筆都要到。本題 `seq` + 「must reach & write out」偏 log 語意 ⇒ queue。ring+dropped 的丟失**顯式可審計**,conflation 的丟失**設計上靜默**。正確動作=把它變 clarify 問題:"Do you need every record, or only the latest per core?"
- **面試官說可換 conflation_slot 時**:換插槽、不重開機。出聲唸合約變更:"That changes the loss model: with a ring, loss is accidental and I count it; with a conflation slot, loss is by design."。架構(sleep→wake→sweep→drain-on-stop)不動,只換 per-core 那格。送分三點:滿/dropped/never-block 全蒸發;conflation 天然 budget=1;新代價=torn read 防護(值層協定)+ consumer 可能重讀同筆(用 seq 去重)。一句話:**fan-in + wakeup 是架構,per-core 格是 policy 插槽**。
- **conflation 丟不丟資料的判準**:不是原語屬性,是放進去的操作的屬性——**update 是 replace 就有損,是 merge/fold 就無損**(槽放累計值:producer `fetch_add`、consumer 收割,一筆不丟,加法吸收歷史)。每核一槽 ⇒ 單寫者+單讀者(SPSC 紀律),爭搶在設計層拆掉,剩 cache line 搬運=通訊最低消費。大 struct 的值層協定 = conflation_slot drill 本體(排 8/2 尾或 8/3),到時親手寫。
- **bitmask ready-set 用不用得了**:用得了但本題不回本。`fetch_or` 單發 RMW 邏輯上無等待,物理上全核打同一條 cache line(MESI 乒乓,見 mesi-rmw-atomics 頁)。回本線=**N ≫ 同時活躍數**(讀側省掃 ≫ 寫側爭搶)。類比:select/poll=全掃,epoll=kernel 維護 ready list;fd 幾千活躍幾十→大賺;本題 N=核數、掃描本來就便宜→純虧。面試講回本線,比用或棄都值錢。
- **aggregator 到底幹嘛/消化得完嗎**:目的=把慢集中到一條專用執行緒(producer=ISR top-half 不准慢;aggregator=bottom-half 慢活全歸它;同 `file_io_offload` 形狀)。佇列吸突發、不造容量:總產出 ≤ 吞吐 → 掃描成本是零頭、sink 才是瓶頸;總產出 > 吞吐 → 結構性超載,任何掃法救不了,只有三路:**丟**(drop+計數;遙測可犧牲、被監控系統不可)/**摺**(fold,M 筆變 1)/**批**(buffer+整輪 flush 攤薄固定成本;budget=K 兼批量旋鈕)。擔心用 sizing 結帳,不用直覺慌。
