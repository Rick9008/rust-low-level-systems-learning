# 7/31 心得卡(reps 收帳 / 卡 SP 重做 / sim j 全場)

用法:蓋住答案自測;晚上出聲場可挑 2–3 張唸英文句;8/5 taper 全掃一輪。

---

**Q1. 量級題的交付格式?**
五行頭:`Given / Chain / Cross / Sanity / Verdict`。動筆先寫五個行頭,五行不滿不准收筆;
Given 的數字用一個劃一個,有剩 = 你在答別題。(骨架+滿分卷示範:capacity-four-shapes.html 分頁②)

**Q2. 五行頭各擋哪個病?**
Chain=心算不落紙(÷10s 消失);Given=偷換題(給定沒用完);Cross=掉零(兩路殊途必同歸);
Sanity=數字一出就收筆。評分對象是紙上的鏈,不是腦中的計算。

**Q3. ISR 的執行模型?**
不是 thread,是**劫持一顆核**。單核時 ISR 執行期間全 thread 凍結(等消費者=等你自己擋住的人);
不能 sleep=沒有 task 身分可掛起;拿 thread 可能持有的鎖=單核必死鎖。
`try_push` 的形狀是被這個模型逼出來的,不是 API 品味。

**Q4. ISR 遇 ring Full 的正確動作?**
計數、不重試、**繼續抽乾 FIFO**。樣本守恆:`read 出的每筆 = pushed + dropped`,帳永遠平。
FIFO 不清:硬體層自己覆蓋(隱形丟失)+ edge IRQ 可能不再觸發 → 管線卡死。

**Q5. 「說不定 worker 來得及消化」這直覺怎麼正確兌現?**
不是 ISR 裡 retry(單核必敗、SMP 負期望值),是 **early wake + 繼續抽乾**:
worker 並行清 ring,你迴圈後段的 push 自然成功。同樣上行空間,零空轉。

**Q6. shutdown 協定?**
一對動作,缺一不可:**先 `stop=true`、後 `wake()`**(缺 wake=真機睡死;順序反了=worker 醒來看到舊
flag 再睡,錯過唯一一次 wake)。worker 側:醒後先 re-pop 再驗迴圈條件,否則「stop+新資料同時到」會漏 drain。

**Q7. wake/sleep 合約必問三件?(sim j 主動問到 ✓,卡 SP 漏過)**
"Is a wake **latched** if nobody's sleeping? Do wakes **coalesce**? Any **spurious** wakeups?"
→ 醒來 = hint,不是保證、不是計數;睡前必 re-check。

**Q8. dropped counter 為什麼 Relaxed 夠?什麼時候不夠?**
夠:獨立統計值,沒有其他記憶體靠它同步。
不夠:有人拿它的值當同步訊號(「讀到 N ⇒ 某 buffer 可讀」)——那一刻它是 flag,要 Release/Acquire 配對。

**Q9. 想「再加一層 buffer/thread/map」時,先問哪句?**
「spec 的**有界性**還在嗎?」無界暫存 = 把有界管線悄悄改無界:過載走向 OOM(隱形),
不是受控丟棄(有帳)。要嘛給上界,要嘛不開。(卡 SP 的 VecDeque = scope creep 換皮)

**Q10. assume 槽的用途邊界?**
蓋**環境未知**("Assuming SMP — is that right?"),不蓋自己造的洞(開了無界佇列再 assume 不會 OOM ✗)。
配套:丟棄動作出現的**同一句話**要有它的帳——計數跟著 drop 走,如同單位跟著數字走。

**Q11. state 管道規則?**
全注入或全全域,選一種貫穿。混搭(isr 吃注入、dropped_count 讀 static)=平行測試互相汙染,
10 分鐘內咬人。守恆律是排程無關的——它「破了」先懷疑帳本被誰汙染,不懷疑物理。

**Q12. 併發黑箱測試配方?**
觀察輸出面(out + counter),**poll with deadline**,斷言**不變量**(dropped+logged==N)不斷言排程;
收尾三步 `stop → wake → join`。永遠不要斷言「它何時睡」。
