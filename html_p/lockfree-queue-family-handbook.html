整份手冊一句話 佇列的難度只由一件事決定:每個 cursor 有幾個寫者。單寫者的 cursor,一對 release/acquire 就活;多寫者的 cursor,就得上 CAS 排隊搶號。SPSC 兩個 cursor 都是單寫者,所以零 CAS、天然 wait-free;MPMC 兩端都在搶,所以兩顆 CAS,還得替 「搶到號 ≠ 交完貨」補一張 per-slot 回條(sequence)。

2×2 地圖:CAS 出現在哪裡

點任一象限直接跳到該章。tail = 進貨端 cursor, head = 收貨端 cursor。徽章標的是「這個 cursor 有幾個寫者」。

SPSC

tail1 寫者 (P)免 CAS
head1 寫者 (C)免 CAS
兩對 release/acquire 打天下 → wait-free。整個家族的地基。

MPSC

tailN 寫者CAS / swap
head1 寫者 (C)免 CAS
只解一端 → 難度砍半。channel / logger 匯流的形狀。

SPMC

tail1 寫者 (P)免 CAS
headN 寫者CAS
先問語意:搶著做(work-stealing)還是都要看(broadcast)?兩種是不同結構。

MPMC

tailN 寫者CAS
headN 寫者CAS
兩端都搶 → 光有 cursor 不夠,還需要 per-slot sequence 回條。

日常說「lock-free queue」多半指「不用 mutex」。正式定義嚴格得多—— 面試被追時能分清「無鎖」≠「lock-free 保證」,並指得出 Vyukov 落在哪(下一章有現場), 是 senior 訊號。

Publication:release / acquire 是唯一的資料通道

核心規則 非原子資料要跨 thread,必須掛在某條 store→load 邊上被發佈:寫方 Release-store 一個旗標,讀方 Acquire-load 到那個值 → 兩者 synchronizes-with → 旗標之前的所有寫入 happens-before 讀方之後的讀取。 找不到那條邊,就是 data race。本書每個結構的分析都只有一個動作:把每一格 data 的兩條邊(發佈、回收)指出來。

降級紀律(你既有的原則,原文照錄):先全 seq_cst 寫對, 再對指得出 synchronizes-with 邊的位置降到 acquire/release;講不出那條邊的,不准降。 Relaxed 只留給「單寫者讀自己」與「純仲裁/計數」。

CAS:取號機的物理

  • compare_exchange(cur, new):值仍是 cur 才換成 new,原子完成; 失敗回傳實際值——這是免費的重讀,retry loop 直接吃它。
  • weak vs strong:weak 允許 spurious fail(LL/SC 架構上更便宜)。反正在 loop 裡 → 用 weak; 一次性判定才用 strong。
  • CAS 的 ordering 可以很弱:若它只負責「仲裁誰贏」、不發佈資料 (資料另有 release/acquire 邊),Relaxed 就夠——Vyukov 的兩顆 cursor 正是教科書案例。

ABA:CAS 的盲點

CAS 只比對值,不比對歷史。head 從 A→B→A,你的 CAS(A→…) 誤判「沒人動過」而成功——但 A 已經是重生後的 A(node 被 free 又 malloc 回同位址; 或 arena 的 slot 5 被回收又重發)。GC 語言天然遮蔽它(舊 A 有人引用就不會重生); C++/Rust 正面撞上。

解法 = 給值加上歷史:generation / tag。 CAS 比對 [generation | index] 整包,slot 每次重用 generation++。 ——這跟你 arena+index 的 generation-tagged index 是同一招:pointer-ABA 換皮成 index-ABA,解法同構。而 Vyukov 的 per-slot sequence 是它的更漂亮形態:回條本身就計圈。

False sharing:兩個熱變數住同一條 cache line

Cache 一致性以 line(常見 64B)為單位。head 和 tail 若同住一條 line,producer 每次 推進 tail 都會把 consumer 手上的 line 打成 invalid——兩個「毫無邏輯衝突」的變數在硬體層 互相打架,吞吐掉一個量級是常態。解法一行:#[repr(align(64))] 把每個熱 cursor 包進自己的 line(crossbeam 的 CachePadded 同理;新硬體上 128B 對齊更保險, 考量 prefetcher 成對抓 line)。

Reclamation:unbounded lock-free 的真 boss

pop 下來的 node 誰敢 free?別的 thread 可能剛 load 到它的指標、還沒 CAS——直接 free = use-after-free。四條路:

  • hazard pointer:讀者先公告「我正在用這顆」,回收方掃過公告欄再 free。精準、每讀有成本。
  • epoch-based(crossbeam-epoch):讀者進出「世代」,整代退場才批次回收。攤銷便宜、延遲回收。
  • arena + generation tag(你的差異化答案):node 全預配、index 互指、永不 free 單顆, 回收 = 還 slot 進 free list;ABA 用 tag 擋。代價:容量上限 + free list 自身的併發。
  • slot 重用(bounded 天然免疫):格子永遠不 free、只換狀態—— Vyukov 正是靠這條把 reclamation 整題繞掉。這是「bounded vs unbounded」在 lock-free 世界真正的分水嶺。

驗證:並發正確性不可 fuzz

Data race 是 timing 依賴的:隨機跑一萬次,那個壞 interleaving 可能 永遠不出現(你 R1 的 200k uniform fuzz 抓不到 wrap off-by-one,並發只會更糟)。 Rust 用 loom 窮舉所有合法 interleaving + 記憶體序;unsafe 疊加 Miri 抓 UB; C++ 用 TSan。面試講出「這類結構我不 fuzz,我窮舉 interleaving」本身就是加分句。 本書附碼的多執行緒測試是 smoke(而且本機單核,交錯覆蓋有限)——正式驗證請 loom。
一句話直覺 兩個人各自只推自己的里程表(producer 推 tail、consumer 推 head), 互相用 release/acquire 偷看對方的。沒有任何變數有兩個寫者 → 一顆 CAS 都不用。

推導:state 不是天上掉下來的

  1. Naive:Mutex<VecDeque>。正確地板,先寫這個永遠不丟人。
  2. 觀察 ①:這個場景裡 tail 只有 producer 寫、head 只有 consumer 寫。 互斥鎖在保護的「同時寫」根本不存在——需要的只剩可見性順序:data 要先於 index 被看見。 → 鎖退場,換兩對 release/acquire(觀念底盤·Publication)。
  3. 第一版:head/tail 追著物理格子跑(到 N 歸零)。反例: head == tail 到底是空還是滿?歧義。
  4. 三條修法:(a) 永遠空一格(head==tail 空、差一格滿)——可行,浪費一格; (b) 加一顆 len 計數——兩端都要寫 len → 憑空造出一個 雙寫者變數,整個單寫者結構被一顆計數器毀掉,這是核心洞見的反面教材; (c) index 單調遞增、永不歸零:滿 = tail-head==N, 空 = tail==head,取位 = idx & (N-1)。
  5. 選 (c):N 取 2 的冪,unsigned wraparound 是 defined behavior (Rust 顯式 wrapping_sub),差值算術跨 usize 溢位仍正確。 兩個「里程表」就是這個結構的全部 state——每一個都被推導逼出來,不是背出來。

兩條同步邊:每格 data 的一生

邊 1 · 資料發佈
producer:寫 data → Release-store tail
consumer:Acquire-load tail → 讀 data
保證:寫入 happens-before 讀取。少了它 = 讀到半成品。
邊 2 · 空間回收
consumer:讀完 data → Release-store head
producer:Acquire-load head → 覆寫該 slot
保證:讀取 happens-before 覆寫。平時隱形,wrap 時刻現形—— 最常被漏掉的一條,漏了 = producer 蓋掉 consumer 正在讀的格子。

自己的 index 讀自己 → Relaxed(單寫者,無序可言); 寫自己的 index → Release;讀對方的 index → Acquire。三行講完整份 ordering 表。

Stepper:含 wrap 與非原點邊界

效能角:把 acquire 的 cache miss 也省掉

Cached 對方 index(rigtorp / folly 都做):producer 把上次看到的 head 存成本地普通變數;只有看似滿了才真的 Acquire 重讀一次。常態 push 於是 零共享讀取——只碰自己的 cache line。這招把 SPSC 推到「吞吐幾乎不隨負載變化」的境界, 也是它在效能表上一枝獨秀的原因(效能章有定位)。 再上去是 batch push/pop:一次搬一批、攤掉 index 更新。

場景

  • audio callback → 混音 thread:callback 內不可 block、不可 alloc、不可等鎖—— wait-free 是硬需求,SPSC 是這裡的唯一正解等級。
  • per-thread logger 前緩衝:每條業務 thread 一條 SPSC 進 logger(N 條 SPSC 勝過一條 MPSC 的常見理由:寫端零競爭;代價是收端要輪詢 N 條)。
  • 網卡收發 ring 的概念原型、pipeline 相鄰 stage 間的手遞手。
  • 你的 telemetry 單線 ingestion:滿了丟最舊 + 計數 —— 就是 7/19 彩排題的形狀。
一句話直覺 多人往同一個信箱丟信,只有一個郵差收。收件端保住單寫者 → 維持 SPSC 級簡單; 只有投遞端要排隊。難度 = 半顆 MPMC。

為什麼比 MPMC 簡單一半

對照 2×2 地圖:head 仍是單寫者 → dequeue 端整套免 CAS。要解的只剩「多個 producer 搶 tail」一件事。兩種典型建法,對應 bounded / unbounded:

建法 A · bounded:半顆 Vyukov

直接拿 Vyukov MPMC 把 dequeue 端退化:dpos 單寫者 → CAS 換成普通 Relaxed store。 enqueue 端與 per-slot seq 原封不動。讀懂 Vyukov 之後這個版本是免費的——也是延伸題 ②。

建法 B · unbounded:Vyukov intrusive MPSC(swap 鏈)

push 三步:node.next = null → prev = tail.swap(node) → prev.next = node。 妙處:swap(xchg)必定成功,沒有 CAS retry storm,高競爭下吞吐極穩。

代價:第 2、3 步之間被 deschedule → 鏈是斷的。tail 已指向新節點, 但 prev.next 還沒接上——consumer 從 head 走鏈會撞到 null,明明 tail 在遠方卻走不到: 「看得到尾巴、追不上」。consumer 此時只能回頭說「暫時沒貨」等它復工—— 與 Vyukov 的停滯取號者同款味道:實務 non-blocking,正式定義非 lock-free。
① swap 完成
tail ──────────► [N]
head ► [A]─►[B]─► ∅   [N]
新節點 N 已被 tail 認領,但還沒人指向它。

consumer 走到 B.next = ∅
但 tail ≠ B → 「有貨但追不到」

consumer 下次輪詢即恢復。xchg 的代價收在這扇窗裡。

生態對號

  • std::sync::mpsc —— 名字就把語意講死了:MPSC,不是 MPMC。 底層近年已改為 crossbeam 的移植版(憑記憶,版本號不背)。Receiver 不可 clone 正是 「head 單寫者」這條不變式的型別化。
  • tokio::sync::mpsc —— bounded + async backpressure: 滿了不是 spin 也不是 Err,是 .await 讓出——把「等空位」交給排程器。 backpressure 從 API 形狀就內建,這是它跟裸佇列最大的差異。
  • flume、各家 actor mailbox —— 同一形狀的變奏。

場景

  • logging 匯流:N 條業務 thread → 1 條 writer。你的 Asio log daemon 論述掛在這: bounded + 滿載策略(丟棄計數 / 阻塞 / 降級)就是 backpressure 故事本體。
  • actor mailbox / event loop 收件匣:誰都能投遞、只有 owner 消化—— 單消費者同時是免鎖處理內部狀態的授權書(所有狀態只被 consumer thread 碰)。
  • 面試判別句:「只有一個消費者」出現的瞬間,不要拿 MPMC 硬上——你多付的那顆 head CAS 一點東西都沒買到。
一句話直覺 + 第一個 clarify 一個發、多人接——但「接」有兩種完全不同的意思:搶著做(每件事恰好一人拿走) 還是 都要看(每個 consumer 看到全部)?這是兩個問題域、兩套結構。 面試被丟「SPMC」先問這句,本身就是 pillar 1 的分。

語意 A · 競爭消費:半顆 MPMC

最小改動版:tail 單寫者照舊,head 變多人搶 → head 推進改 CAS loop。 機制上就是 MPMC 拆一半(鏡像於 MPSC)。實務上很少以這個裸形狀存在——單一 producer 的分派場景幾乎都演化成下面兩條路之一:每個 consumer 一條 SPSC(寫端零競爭、 收端犧牲彈性),或者 work-stealing(平時零競爭、失衡才偷)。

語意 A 的王者:Chase-Lev work-stealing deque

  1. 觀察:分派場景裡 owner(worker 自己)的 push/pop 是高頻熱路徑, 小偷(其他 worker)只在失衡時才來。讓高頻方付 CAS 是本末倒置。
  2. 結構:owner 獨占 bottom 端自由 push/pop (單寫者 → 免 CAS!),所有小偷去 top 端 CAS 搶。 常態下 owner 完全不感覺別人存在——把「單寫者免 CAS」原則用成非對稱設計。

語意 B · Broadcast:每個人都要看到

LMAX Disruptor 型:producer 推全域 sequence, 每個 consumer 自己維護消費進度(N 個 cursor,各自單寫者——又是同一條原則); producer 發佈前 gating 於最慢的 consumer,防止繞圈蓋掉沒讀完的格子 → backpressure 天然內建。batch claim 一次領一段號,把 cursor 更新攤薄。

seqlock:如果語意再退化成「只要最新值」(config 快照、行情最新價), 連佇列都不用——版本號雙讀 + 重試,讀者 wait-free、零 alloc。

一句話直覺 兩端都有人搶。搶號用 CAS——但「搶到號」不等於「交完貨」。 所以每個格子還需要一張「完工回條」,那張回條,就是 per-slot sequence。

推導:sequence 是被兩個反例逼出來的

  1. Naive:Mutex<VecDeque>。低競爭下經常直接夠用 (效能章有它的名譽保衛戰)。往下走的前提是 「量到了 contention」。
  2. 第一版 lock-free:兩顆 cursor 都上 CAS,producer 搶到 epos 的號就往對應 slot 寫。反例走一遍:P1 贏得號 0、 還沒把 data 寫完就被 deschedule;consumer 看 dpos=0 < epos=1 以為有貨 → 讀到未初始化記憶體。→ cursor 只能證明「號碼發出去了」, 證明不了「資料寫好了」。
  3. 第二版:每格補一顆 ready: AtomicBool (寫完 set true、讀完 set false)。反例:繞到第 2 圈,producer 看到一顆 true—— 是這一圈consumer還沒收的 true,還是上一圈殘留的 true?flag 無法區分圈數, 滿/空判斷跨圈歧義——這就是 ABA 換了件衣服。 → 回條需要自帶「第幾圈」。
  4. 把 bool 升級成計圈的 seq: AtomicUsize, 一個變數同時當「狀態」和「圈數」:
    seq == pos → 本圈空位票,輪到號 pos 的 producer;
    seq == pos+1 → 本圈貨到回條,輪到號 pos 的 consumer;
    consumer 讀完寫 seq = pos+cap → 恰好是下一圈同格 producer 期待的票號。 ready flag 與 lap counter 融合 → Vyukov bounded MPMC 誕生 (crossbeam ArrayQueue 走的正是這條)。slot 永遠重用、永不 free → reclamation 整題繞掉。

Ordering 逐條表:同步全掛在 seq 上

操作Ordering理由(照你今晚 drill 的格式:一行一個)
epos/dpos loadRelaxed只是猜號;猜錯 CAS 會用實際值糾正,不承載任何資料可見性
slot.seq loadAcquire同步邊接收端:接住對面的 release,才保證 data(或「已清空」)可見
cursor CASRelaxed / Relaxed純仲裁「號歸誰」;資料不走這裡 → 成敗兩個 ordering 都能弱
data write/read非原子由 seq 協議保護:同一格同一圈,寫權/讀權都是獨家
slot.seq storeRelease發佈端:enqueue 發佈 data、dequeue 發佈「我讀完了」——SPSC 兩條邊的合體,只是搬到 per-slot
看懂這張表 = 回答了「哪一條 store→load 邊在發佈資料」: 是 slot.seq 的 Release→Acquire,從頭到尾與兩顆 cursor 無關。 這就是「cursor CAS 可以 Relaxed」的完整理由——也是 acquire/release 從 seq_cst 降級的教科書示範。(完全形式化的論證交給 loom;口試講到這層已經超標。)

Stepper:兩個 producer 對撞 + 停滯現場 + 圈數算術

誠實邊界:Vyukov 不滿足正式 lock-free 定義

Stepper 第 6 幀就是證據:一個搶到號、還沒交貨就停滯的 producer, 讓所有 consumer 空手而回——系統整體無人前進,違反 lock-free 的定義, 正式歸類是 blocking。實務上大家仍叫它 lock-free / non-blocking,因為停滯窗只有幾條指令寬、 且無鎖可持有(不會死鎖、不怕 priority inversion 持鎖方餓死)。 面試把「慣稱」與「正式定義」分開講,並指出停滯窗在哪兩行指令之間 = 真懂的訊號。

Unbounded 的正統:Michael-Scott queue(論述級)

結構
head ►[dummy]─►[A]─►[B]─► ∅ ◄ tail
enqueue: ① CAS tail.next: ∅→N
         ② CAS tail: →N (swing)
dequeue: CAS head 前移,回傳新 head 的值
dummy node 解耦 head/tail:空佇列、單元素時兩端不撞同一顆 node, 少掉一整類邊界分支。
help-advance:①②之間 tail 落後一步是合法中間態—— 任何 thread 發現 tail.next ≠ ∅ 都可以幫忙把 tail 推上去再繼續自己的事。 正確性靠「中間態可辨識 + 修復動作冪等」;這是 lock-free 設計裡「大家一起收拾殘局」的 代表手法,對照 Vyukov 的「停滯者無人能幫」正好一組對比。
真 boss 在 reclamation: pop 下來的 node 直接 free = UAF,必配 hazard / epoch / arena+tag。 手寫定位(prep plan 原話):結構 + 兩步 CAS + reclamation 三條路的論述; 25 分鐘默寫 production-correct 版對強工程師都是大 ask,投報率斷崖。

點名其餘家族成員(各一句)

  • moodycamel::ConcurrentQueue(C++):per-producer sub-queue,寫端幾乎零競爭; 代價是不同 producer 之間沒有全序 FIFO——「你的佇列語意到底承諾什麼」的最佳考題。
  • folly::MPMCQueue:ticket / turn 家族,取號後各自等自己的 turn,Vyukov 的近親。
  • crossbeam SegQueue:unbounded、分段鏈結——塊內像 bounded、塊間像 linked,兩邊優點各拿一半。
  • LCRQ 一族:fetch-add 取號的學術前沿,知道存在即可。
效能一句話 吞吐上限 ≈ 最熱那條共享 cache line 的易手速率。所有佇列效能分析, 最後都是在數「有幾條熱 line、幾個核在搶」。

用 cache line 重讀 2×2 地圖

序列化點論證(面試可整段搬):MPMC 每筆 enqueue 都要對同一顆 epos 完成一次成功 CAS——不管幾個核,這顆 cursor 的更新天生全序, 每次易手要吃一趟跨核 line 轉移。所以吞吐上限 ≈ 1 / (line 易手延遲), 與核數無關;超過飽和點再加 producer,只是把功耗換成 CAS retry, 吞吐反而下降。這也是「把一條 MPMC 拆成 per-worker 佇列」的根本理由。

Mutex 的名譽保衛戰(先量再換)

lock-free 真正買到的
  • 尾延遲可預測:沒有「持鎖者被 deschedule,全隊陪睡」
  • 無 priority inversion、無死鎖組合爆炸
  • 可用於不可阻塞情境:audio callback、signal handler
  • contention 下退化曲線平緩
lock-free 沒承諾的
  • 平均吞吐未必贏:uncontended mutex ≈ 一顆 CAS
  • 程式碼複雜度、驗證成本(loom)全額自付
  • Vyukov 一族還不給正式 progress 保證
  • 飽和區照樣 line 乒乓,物理不可豁免

結論句(拿去面試用):「我會先 Mutex<VecDeque> + condvar 拿到正確性,量到 contention 證據再按競爭形狀換型—— 直接跳 lock-free 顯得沒判斷。」

SPSC ring(drill 對答案用)

// spsc.rs — SPSC ring buffer, std-only, 2024-edition-compatible
// 驗證:rustc --edition 2021 -O spsc.rs && ./spsc   (asserts-in-main,全綠無輸出即通過)
#![deny(unsafe_op_in_unsafe_fn)]
use std::cell::UnsafeCell;
use std::mem::MaybeUninit;
use std::sync::atomic::{AtomicUsize, Ordering::{Acquire, Relaxed, Release}};
use std::sync::Arc;
use std::thread;

#[repr(align(64))]
struct Pad<T>(T); // head / tail 各自獨占一條 cache line,避免 false sharing

struct Inner<T, const N: usize> {
    buf: [UnsafeCell<MaybeUninit<T>>; N],
    head: Pad<AtomicUsize>, // 只有 consumer 寫(單調遞增,永不歸零)
    tail: Pad<AtomicUsize>, // 只有 producer 寫(單調遞增,永不歸零)
}

// 安全論證:data 的存取由 head/tail 協議獨占(producer 只碰 [head,tail) 之外、
// consumer 只碰 [head,tail) 之內),兩條 release/acquire 邊保證可見性。
unsafe impl<T: Send, const N: usize> Send for Inner<T, N> {}
unsafe impl<T: Send, const N: usize> Sync for Inner<T, N> {}

pub struct Producer<T, const N: usize>(Arc<Inner<T, N>>);
pub struct Consumer<T, const N: usize>(Arc<Inner<T, N>>);

pub fn spsc<T, const N: usize>() -> (Producer<T, N>, Consumer<T, N>) {
    assert!(N.is_power_of_two(), "N 必須是 2 的冪:& (N-1) 取位、wrap 判滿都依賴它");
    let inner = Arc::new(Inner {
        buf: std::array::from_fn(|_| UnsafeCell::new(MaybeUninit::uninit())),
        head: Pad(AtomicUsize::new(0)),
        tail: Pad(AtomicUsize::new(0)),
    });
    (Producer(inner.clone()), Consumer(inner))
}

impl<T, const N: usize> Producer<T, N> {
    pub fn push(&mut self, v: T) -> Result<(), T> {
        let q = &*self.0;
        let t = q.tail.0.load(Relaxed);   // 自己的 index:單寫者,讀自己 → Relaxed
        let h = q.head.0.load(Acquire);   // 邊2 接收端:看到 consumer 的 release(head)
                                          //   才保證 slot 舊值已被讀完,可以覆寫
        if t.wrapping_sub(h) == N {       // 滿:單調 index 差值判滿,不浪費格
            return Err(v);
        }
        unsafe { (*q.buf[t & (N - 1)].get()).write(v); }
        q.tail.0.store(t.wrapping_add(1), Release); // 邊1 發佈端:data 寫入
                                                    //   happens-before 這個 store
        Ok(())
    }
}

impl<T, const N: usize> Consumer<T, N> {
    pub fn pop(&mut self) -> Option<T> {
        let q = &*self.0;
        let h = q.head.0.load(Relaxed);   // 自己的 index → Relaxed
        let t = q.tail.0.load(Acquire);   // 邊1 接收端:同步到 producer 的
                                          //   release(tail),data 可見
        if t == h {                       // 空
            return None;
        }
        let v = unsafe { (*q.buf[h & (N - 1)].get()).assume_init_read() };
        q.head.0.store(h.wrapping_add(1), Release); // 邊2 發佈端:「這格我讀完了」
        Some(v)
    }
}

impl<T, const N: usize> Drop for Inner<T, N> {
    fn drop(&mut self) { // 兩個 handle 都掛了才會走到這:獨占,安全清場
        let mut h = *self.head.0.get_mut();
        let t = *self.tail.0.get_mut();
        while h != t {
            unsafe { (*self.buf[h & (N - 1)].get()).assume_init_drop(); }
            h = h.wrapping_add(1);
        }
    }
}

fn main() {
    // ── 單執行緒精確測試(含滿 / 空 / wrap / 非原點邊界)──
    let (mut p, mut c) = spsc::<u64, 4>();
    assert_eq!(c.pop(), None);                       // 初始為空
    for i in 0..4 { assert!(p.push(i).is_ok()); }
    assert_eq!(p.push(99), Err(99));                 // 滿(t-h==4)
    assert_eq!(c.pop(), Some(0));
    assert_eq!(c.pop(), Some(1));
    assert!(p.push(4).is_ok());                      // t=4 → slot 0:跨 wrap 寫入
    assert!(p.push(5).is_ok());                      // t=5 → slot 1
    assert_eq!(p.push(99), Err(99));                 // 非原點的滿:h=2, t=6
    for want in 2..6 { assert_eq!(c.pop(), Some(want)); } // FIFO 保持
    assert_eq!(c.pop(), None);                       // 非原點的空:h==t==6
    // 再繞幾圈,確認 lap 算術與 slot 重用
    for lap in 0..3u64 {
        for i in 0..4 { assert!(p.push(lap * 10 + i).is_ok()); }
        for i in 0..4 { assert_eq!(c.pop(), Some(lap * 10 + i)); }
    }

    // ── 雙執行緒 smoke:100k 筆,驗證嚴格遞增(FIFO + 不丟不重)──
    const M: u64 = 100_000;
    let (mut p, mut c) = spsc::<u64, 8>();
    let prod = thread::spawn(move || {
        for i in 0..M {
            let mut v = i;
            loop {
                match p.push(v) {
                    Ok(()) => break,
                    Err(back) => { v = back; thread::yield_now(); } // 滿了讓路
                }
            }
        }
    });
    let cons = thread::spawn(move || {
        let mut expect = 0u64;
        while expect < M {
            match c.pop() {
                Some(v) => { assert_eq!(v, expect); expect += 1; }
                None => thread::yield_now(),
            }
        }
    });
    prod.join().unwrap();
    cons.join().unwrap();
    println!("spsc: all tests passed");
}

Vyukov bounded MPMC(選練對答案用)

// vyukov.rs — Vyukov bounded MPMC queue, std-only, 2024-edition-compatible
// 驗證:rustc --edition 2021 -O vyukov.rs && ./vyukov
// 註:欄位命名避開 `gen`(2024 保留字),用 seq / lap 語彙。
#![deny(unsafe_op_in_unsafe_fn)]
use std::cell::UnsafeCell;
use std::mem::MaybeUninit;
use std::sync::atomic::{AtomicUsize, Ordering::{Acquire, Relaxed, Release}};
use std::sync::Arc;
use std::thread;

#[repr(align(64))]
struct Pad<T>(T); // epos / dpos 兩顆熱門 cursor 分開躺,別共享 cache line

struct Slot<T> {
    seq: AtomicUsize,                 // 這格的「狀態 + 圈數」合體票
    data: UnsafeCell<MaybeUninit<T>>, // 非原子;由 seq 協議保護
}

pub struct MpmcQueue<T> {
    slots: Box<[Slot<T>]>,
    mask: usize,
    epos: Pad<AtomicUsize>, // enqueue 取號機(多寫者 → CAS)
    dpos: Pad<AtomicUsize>, // dequeue 取號機(多寫者 → CAS)
}

unsafe impl<T: Send> Send for MpmcQueue<T> {}
unsafe impl<T: Send> Sync for MpmcQueue<T> {}

impl<T> MpmcQueue<T> {
    pub fn new(cap: usize) -> Self {
        assert!(cap.is_power_of_two() && cap >= 2);
        let slots = (0..cap)
            .map(|i| Slot { seq: AtomicUsize::new(i), data: UnsafeCell::new(MaybeUninit::uninit()) })
            .collect::<Vec<_>>()
            .into_boxed_slice(); // 初始 seq=i:第 0 圈,slot i 的空位票號就是 i
        Self { slots, mask: cap - 1, epos: Pad(AtomicUsize::new(0)), dpos: Pad(AtomicUsize::new(0)) }
    }

    pub fn push(&self, v: T) -> Result<(), T> {
        let mut pos = self.epos.0.load(Relaxed); // 只是猜號;猜錯 CAS 會糾正 → Relaxed
        loop {
            let slot = &self.slots[pos & self.mask];
            let seq = slot.seq.load(Acquire);    // 同步邊接收端(接對面 dequeue 的 release)
            let diff = seq.wrapping_sub(pos) as isize;
            if diff == 0 {
                // seq == pos:這格是「本圈空位票」→ 去取號機搶這個號
                match self.epos.0.compare_exchange_weak(pos, pos.wrapping_add(1), Relaxed, Relaxed) {
                    Ok(_) => {
                        // 搶到號 = 這格本圈的寫入權獨家歸我
                        unsafe { (*slot.data.get()).write(v); }
                        slot.seq.store(pos.wrapping_add(1), Release); // 貨到回條:發佈 data
                        return Ok(());
                    }
                    Err(actual) => pos = actual, // 沒搶到,CAS 順手告訴我最新號
                }
            } else if diff < 0 {
                // seq 還停在上一圈:上一圈這格的貨還沒被 consumer 收走 → 滿
                return Err(v);
            } else {
                pos = self.epos.0.load(Relaxed); // 號被別人搶走推進了,重新看號
            }
        }
    }

    pub fn pop(&self) -> Option<T> {
        let mut pos = self.dpos.0.load(Relaxed);
        loop {
            let slot = &self.slots[pos & self.mask];
            let seq = slot.seq.load(Acquire);    // 接 push 的 release:看到回條 = data 可見
            let diff = seq.wrapping_sub(pos.wrapping_add(1)) as isize;
            if diff == 0 {
                // seq == pos+1:本圈貨到回條在 → 搶收貨號
                match self.dpos.0.compare_exchange_weak(pos, pos.wrapping_add(1), Relaxed, Relaxed) {
                    Ok(_) => {
                        let v = unsafe { (*slot.data.get()).assume_init_read() };
                        // 讀完發下一圈空位票:pos + cap。release 保證「我讀完了」
                        // happens-before 下一圈 producer 的覆寫(靠對面 Acquire 接住)
                        slot.seq.store(pos.wrapping_add(self.mask).wrapping_add(1), Release);
                        return Some(v);
                    }
                    Err(actual) => pos = actual,
                }
            } else if diff < 0 {
                // 回條還沒出現:可能真的空,也可能 producer 搶了號還沒寫完
                //(← Vyukov 不滿足正式 lock-free 定義的現場)
                return None;
            } else {
                pos = self.dpos.0.load(Relaxed);
            }
        }
    }
}

impl<T> Drop for MpmcQueue<T> {
    fn drop(&mut self) {
        while self.pop().is_some() {} // &mut self 獨占,安全排空
    }
}

fn main() {
    // ── 單執行緒精確測試:滿 / 空 / wrap / 非原點圈數 ──
    let q = MpmcQueue::<u64>::new(4);
    assert_eq!(q.pop(), None);
    for i in 0..4 { assert!(q.push(i).is_ok()); }
    assert_eq!(q.push(99), Err(99));                  // 滿:slot0.seq 停在上一圈
    assert_eq!(q.pop(), Some(0));
    assert!(q.push(4).is_ok());                       // 進第二圈:slot0 重用
    for want in 1..5 { assert_eq!(q.pop(), Some(want)); }
    assert_eq!(q.pop(), None);                        // 非原點空:dpos==epos==5
    for lap in 0..5u64 {                              // 多繞幾圈驗 lap 算術
        for i in 0..4 { assert!(q.push(lap * 100 + i).is_ok()); }
        assert!(q.push(777).is_err());
        for i in 0..4 { assert_eq!(q.pop(), Some(lap * 100 + i)); }
    }

    // ── 多執行緒 smoke:2 producers × 2 consumers,50k×2 筆 ──
    // 驗證:(a) 不丟不重(全域 seen 表);(b) 單一 consumer 視角內,
    //       每個 producer 的元素序號嚴格遞增(ticket 序 ⇒ per-producer FIFO)
    const PER: u64 = 50_000;
    let q = Arc::new(MpmcQueue::<u64>::new(8));
    let done = Arc::new(AtomicUsize::new(0));
    let mut handles = Vec::new();
    for pid in 0..2u64 {
        let q = q.clone();
        handles.push(thread::spawn(move || {
            for i in 0..PER {
                let mut v = (pid << 32) | i; // 高位 producer id,低位序號
                loop {
                    match q.push(v) {
                        Ok(()) => break,
                        Err(back) => { v = back; thread::yield_now(); }
                    }
                }
            }
        }));
    }
    let popped = Arc::new(AtomicUsize::new(0));
    let mut consumers = Vec::new();
    for _ in 0..2 {
        let (q, popped, done) = (q.clone(), popped.clone(), done.clone());
        consumers.push(thread::spawn(move || {
            let mut got: Vec<u64> = Vec::new();
            let mut last = [-1i64; 2];
            loop {
                match q.pop() {
                    Some(v) => {
                        let (pid, i) = ((v >> 32) as usize, (v & 0xffff_ffff) as i64);
                        assert!(i > last[pid], "per-producer 順序被打破");
                        last[pid] = i;
                        got.push(v);
                        popped.fetch_add(1, Relaxed);
                    }
                    None => {
                        if done.load(Acquire) == 2
                            && popped.load(Relaxed) as u64 == 2 * PER { break; }
                        thread::yield_now();
                    }
                }
            }
            got
        }));
    }
    for h in handles { h.join().unwrap(); done.fetch_add(1, Release); }
    let mut seen = vec![false; (2 * PER) as usize];
    for c in consumers {
        for v in c.join().unwrap() {
            let (pid, i) = (v >> 32, v & 0xffff_ffff);
            let idx = (pid * PER + i) as usize;
            assert!(!seen[idx], "重複取出");
            seen[idx] = true;
        }
    }
    assert!(seen.iter().all(|&b| b), "有元素遺失");
    println!("vyukov: all tests passed");
}
