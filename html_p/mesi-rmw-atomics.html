MESI × Atomic RMW — 一貴一便宜的機器層

spin_lock 教材 Q3 的完整版 · 為什麼 swap 貴、load 便宜 · 2026-08-01

出發點:同一個變數,兩種價格

TTAS 自旋鎖的形狀是「外圈 swap 搶鎖、內圈純 load 等待」。兩個操作碰的是同一個 AtomicBool,為什麼一個會打爆匯流排、一個幾乎免費?答案不在 Rust,在 cache 一致性協定。這一頁把機器層一次補齊。

前置:cache line 是交易單位

CPU 不以 byte 為單位跟記憶體打交道,而是以 cache line(通常 64 bytes)為單位。你的 AtomicBool 只有 1 byte,但它所在的整條 64-byte line 才是各核心 cache 之間搬動、共享、作廢的單位。

多核心 = 每核有自己的 L1/L2 cache = 同一條 line 可能同時存在好幾份副本。一致性協定的工作就是讓這些副本不說謊——這就是 MESI。

SWMR 鐵律  同一條 line:一個寫者(M/E) XOR 多個讀者(S)——絕不並存
文件比喻(字面翻譯在後) 很多人可以同時拿影本讀;要改就必須把原稿拿到手,並把所有影本收回作廢。字面意思:核心要寫入一條 line 之前,必須廣播 invalidation 把其他核心的副本全打成 Invalid,自己取得獨占——這個「我要原稿」的匯流排訊息叫 RFO(Read For Ownership)。

MESI 四態

每核 cache 裡的每條 line,隨時處在其中一態
態全名意思可讀?可直接寫?
MModified只有我有,而且改過(比記憶體新,dirty)✓✓
EExclusive只有我有,沒改過(跟記憶體一致)✓✓(靜默升 M)

兩條要背的轉移 寫入路:任何態 → 想寫 → 沒獨占就廣播 RFO(其他核全變 I)→ 自己變 M。
讀取路:I → load miss → 從記憶體或別核拿 → 有其他讀者就大家一起 S;沒有就 E。E 存在的意義:獨自讀的人之後想寫,不用再廣播(反正沒別人),靜默升 M——省一次匯流排訊息。

Stepper:兩核搶一條 line

場景:x 起始為 0,在記憶體裡。逐幀看 C0 / C1 的 load 與 store 如何轉移狀態。第 4 幀有預測題,先答再按 next。

帶走的一句 讀的代價是一次性的(miss 一次,之後停在 S 免費讀);寫的代價是持續性的(每次要寫都得確保獨占,別人有副本就得作廢別人)。RMW 是寫——這就是「一貴一便宜」的全部來源。

Atomic RMW 家族

Read-Modify-Write:讀 → 改 → 寫,三步合一、不可分割

定義

RMW 是一種不可分割的原子操作:從記憶體讀值、修改、寫回,整段期間不會被其他核心插隊。硬體上它必須持有 cache line 獨占直到寫回完成——所以每一次 RMW 都至少是一次「寫」的價格(可能觸發 RFO)。

操作語意會失敗嗎?Ordering 幾個典型用途
swap(v)無條件寫入 v,回舊值不會1搶旗標、換手
Test-and-Setswap(true) 的特例:設旗標、回舊值(舊值 false = 我搶到)不會1spin lock 的心臟
fetch_add(n) 等讀舊值、加 n、寫回,回舊值(fetch_or/and/xor 同族)不會1計數器、引用計數(Arc)
compare_exchange(exp, new)條件寫:目前值 == exp 才寫入 new;回 Result<舊值, 實際值>會2lock-free 演算法、單發 try_lock
compare_exchange_weak同上,但允許 spurious failure(值明明相等也可能失敗)會(含假失敗)2CAS 迴圈裡
fetch_update(f)CAS 迴圈的語法糖:load → 閉包算新值 → CAS,失敗重來閉包回 None 才失敗2複雜更新

為什麼 CAS 要填兩個 Ordering,fetch_add 只填一個

看結局數,不是看「讀寫兩半」:

  • fetch_add / swap 永遠成功——只有一種結局(讀+寫都發生),一個 Ordering 就描述完了。
  • CAS 有兩種結局:成功(讀+寫,套 success ordering)/ 失敗(只有讀,套 failure ordering)。失敗那次沒有寫入,所以 failure ordering 不能是 Release/AcqRel(沒有 store 可以 release),且通常填 Relaxed——沒搶到的人沒有臨界區,不需要可見性保證。

weak vs strong

compare_exchange_weak 在 LL/SC 架構(ARM)上編成更便宜的指令,代價是允許假失敗:值明明等於 expected 也可能回 Err。判準一句話:迴圈裡用 weak(反正會重試),單發用 strong(失敗必須真的代表被佔用)。

實戰案例:今晚 try_lock 的兩個洞(2026-08-01 drill 實錄) 寫成 compare_exchange_weak(false, true, AcqRel, Relaxed),兩個問題:
① weak 用在單發——try_lock 沒有迴圈,假失敗會讓「鎖明明沒人拿」也回 None,呼叫者被騙去走 fallback 路徑;正解 strong。
② 成功側 AcqRel 過度訂購——上鎖的人此刻沒有東西要發佈(要發佈的在解鎖時),Release 半邊是白付的;正解 Acquire。過度訂購不是 bug,但面試裡「說不出每個 Ordering 的理由」就是洞。

對 MESI 的翻譯

所有 RMW(包括失敗的 CAS!)都需要對 line 的獨占存取權才能保證原子性——x86 的 lock 前綴指令就是「把這條 line 鎖在我的 cache 裡直到讀改寫完成」。所以:

RMW = 至少一次獨占索取   ·   純 load = S 態本地命中,零流量

① TAS vs TTAS — 同一場搶鎖,兩張帳單

C0 持鎖中,C1/C2/C3 在等。切換模式,看匯流排訊息計數
// TAS(naive):等待 = 反覆 RMW
while lock.swap(true, Acquire) { /* 空轉 */ }

// TTAS:等待 = 純 load;看似有空才出手 swap
loop {
    if !lock.swap(true, Acquire) { break; }        // 出手(貴,RFO)
    while lock.load(Relaxed) { spin_loop(); }         // 等待(免費,S 態)
}
兩張帳單的差 TAS:等待期間每一輪每個等待者都是一次 RFO,line 在等待者之間乒乓,持鎖者要放鎖時還得跟他們搶——等的人越努力,放的人越慢。TTAS:等待期間零流量(大家 S 態各讀各的),流量只集中在釋放瞬間的一波。

② 釋放瞬間 — TTAS 的殘留弱點

等待期安靜了,但 unlock 那一刻還有一場驚群

C0 放鎖的那個 store(false, Release) 會把所有 spinner 的 S 副本作廢。接下來逐幀看會發生幾次 miss、幾次 RFO、幾個人搶到。

升級路:各解什麼

方案解掉什麼沒解掉什麼 / 代價
exponential backoff:搶輸就隨機退避漸長把驚群錯開,RFO 波變稀公平性更差(剛到的可能比等最久的先搶到);延遲抖動
ticket lock:取號 fetch_add,等叫號公平(FIFO,不飢餓)流量沒解——所有人 spin 同一個叫號器,釋放仍全體 miss
MCS / CLH:排隊節點,各自 spin 自己的 line流量+公平都解:釋放只戳下一位的私有 line,O(1) 訊息結構複雜、要傳 node;kernel 的 qspinlock 就是這家族
睡覺(futex / parking)不燒 CPU;等待者無限多也沒流量睡/醒是 syscall(µs 級)——臨界區奈秒級時反而比自旋貴,繞回 spin lock 的存在理由
接回你的教材 spin_lock 教材的〔Trade-offs〕說「不公平,升級路 = ticket lock」——現在你可以說得更準:ticket 買的是公平,買不到流量;要流量得上 MCS。面試被追問「TTAS 之後呢」,這張表就是答案的骨架。

30 秒英文句庫

  • "A spinning atomic swap is a write — under MESI every attempt needs exclusive ownership of the cache line, so N spinners just ping-pong the line and saturate the interconnect. A plain load spins on a Shared copy in the local cache: zero coherence traffic while waiting."
  • "TTAS splits waiting from acquiring: wait with reads, acquire with one RMW. The residual cost is the thundering herd at release — everyone misses, re-fetches, and races one RFO each. Backoff spreads that burst out; a ticket lock adds fairness; MCS makes each waiter spin on its own line."
  • "CAS takes two orderings because it has two outcomes: success is a read-modify-write, failure is just a load — nothing to release. Use _weak inside retry loops, strong for one-shot attempts like try_lock."

自測(先答再翻)

1. E 態存在的意義是什麼?拿掉它(只剩 MSI)會多付什麼? 獨自持有且乾淨的線,想寫時可以靜默升 M,不用廣播。MSI 協定裡同樣情境要多付一次 invalidation 廣播——單執行緒反覆讀寫自己的資料就會白繳匯流排稅。
2. 失敗的 CAS 有沒有流量成本? 有。要保證「比較+寫」原子,硬體得先拿獨占(或至少擁有權)才能裁決——所以連失敗的 CAS 都可能觸發 RFO、作廢別人的副本。這正是 TAS 迴圈貴的原因:失敗的嘗試不是免費的。
3. TTAS 內圈看到 false 之後,為什麼還要回外圈重新 swap,不能直接進臨界區? load 看到 false 只代表「剛剛」沒鎖——從 load 到你動作之間別人可能已搶走。裁決權在那次原子 swap;load 只是省 RMW 的提示。
4. 釋放瞬間 N 個 spinner:幾次 miss、幾次 RFO、幾人得手? unlock 的 store 作廢全部 S 副本 → N 次 miss 重抓 → 全看到 false 回外圈 → N 次 swap = N 次 RFO 串行化 → 恰一人得手,其餘 N−1 人看到 true 回內圈。一次釋放 ≈ 2N 條匯流排訊息——這就是 backoff/MCS 要解的帳。
5. 為什麼 Arc::clone 的 fetch_add 用 Relaxed 就夠,drop 端卻要 Release? clone 只需要「計數原子遞增」,不護送任何資料——所有權論證保證你手上本來就有合法引用。drop 是遺言:遞減前的所有使用必須對「最後一個遞減、負責釋放的人」可見,所以 Release(配 winner 的 Acquire fence)。RMW 的原子性(不掉計數)與 Ordering(可見性)是兩件獨立的事。
