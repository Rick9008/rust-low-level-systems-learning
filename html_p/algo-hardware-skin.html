boot planner — 一趟 Kahn 做三件事

drill:drills/src/ds/boot_planner.rs(8/3 開機槽)。波次分層、最長路徑 DP、環偵測,全在同一個迴圈裡。

題目的圖(stepper 用同一張)

「a 必須先開完,b 才能開始」= 有向邊 a→b。要回答三個運維問題:哪些可以同時開(波次)、整機最快幾 ms 全亮(makespan)、催哪條鏈最有效(關鍵路徑)。

Stepper:正常模式(波次+DP)⇄ 有環模式(pred-walk 抓環)

金句(面試講出來就是分) 「一般圖的最長路徑是 NP-hard,DAG 上是 P——因為無環,沿 topo 序每個節點定案後就不會再變,DP 一遍就對。」這句話同時解釋了你為什麼敢做、以及為什麼要先跑拓撲。
環回報:為什麼 pred-walk 一定找得到 Kahn 收不完 ⇒ 殘餘節點的 indeg 都 > 0 ⇒ 每個殘餘節點都至少有一個殘餘前驅(已處理的前驅早就把它的 indeg 減掉了)。沿前驅走,有限節點必重訪,重訪點就在環上。比 DFS 三色標記少一整套狀態機。

widest path — Dijkstra 的鏡像雙胞胎

drill:drills/src/ds/route_planner.rs。認題關鍵在題面那句 "the minimum link bandwidth along the path"——這不是最短路。

反例圖(短窄 vs 長寬)

最短路(Dijkstra)widest path(本題)
優化目標路徑和最小路徑最小值最大
鬆弛cand = dist[u] + wcand = min(bott[u], w)
堆min-heap(Reverse)max-heap(std 原生,不包 Reverse)
貪婪為什麼成立距離沿路徑單調不減瓶頸沿路徑單調不增(min 只會變小)

Stepper:兩處變形逐幀走

帶走的一句 "This is widest path, not shortest — same Dijkstra skeleton, two swaps: min instead of plus, max-heap instead of min-heap. The greedy argument survives because the bottleneck is monotone non-increasing as a path grows." 講完這句,實作只是抄你自己 repo 的 Dijkstra 改兩行。

聚合樹修復 — 孤兒是整棵子樹

drill:drills/src/ds/aggregation_tree.rs。目標函數 spec 故意沉默——「最小化什麼」是必問的 clarify。

場景圖(stepper 用同一棵)

兩個藏起來的陷阱 ① 安置目標不得在孤兒子樹內部——把 3 掛到自己的子孫底下 = 環,樹解體。排除整片孤兒區最乾淨。② dead 的 parent 因為 dead 離隊,自動多出一格 slack——把 dead 和孤兒區一起標 banned 再數「未 banned 孩子」,這格不用特判就自己浮出來。

Stepper:slack 掃描 → 大子樹先入座

收尾句(trade-off 三拍) "Shallow-first placement bounds depth growth — good for aggregation latency — but can concentrate load; balance-first spreads load but deepens paths. Optimal placement is bin-packing-flavored, so in 45 minutes I take the greedy and state the bound."

句庫與判準

algo 穿皮題的英文定界句 + Big-O 表 + 判準速查。

30 秒英文定界(每題一句)

題句子
boot planner"This is a DAG problem in provisioning clothes: Kahn's toposort gives me the waves for free, the longest path — which is polynomial exactly because the graph is acyclic — gives the makespan and critical path, and if Kahn can't finish, the leftover nodes contain the cycle, which I extract by walking predecessors."
widest path"The route's bandwidth is the minimum along the path, so this is widest path, not shortest: Dijkstra with min instead of plus, and a max-heap instead of a min-heap. Same greedy proof, mirrored."
tree rehome"Orphans are whole subtrees, so I only choose new parents. I sweep the surviving tree shallow-first collecting slack — the dead node's parent frees one slot automatically — and place the largest subtree first. Optimal is bin-packing; I'll take the greedy and say why."

Big-O 表(講得出來的那種)

題時間一句話理由
boot plannerO(V + E)(+每波排序)每節點進出 frontier 一次、每邊鬆弛一次
widest pathO((V+E) log E)懶刪除 ⇒ 堆內最多 E 條目,同你 repo 的 Dijkstra
tree rehomeO(V + k log k)一趟 BFS 收位、k 個孤兒排序

判準速查

看到想到
"before" 依賴語言DAG + Kahn;「回報環員」比「偵測有環」多一步 pred-walk
"minimum along the path"widest path,Dijkstra 鏡像;千萬別寫成最短路
"max fan-in" / 容量slack 記帳 + greedy;最優 = bin-packing,聲明不做
"which nodes are affected"前向/反向可達 BFS;方向想清楚(影響誰 vs 被誰影響)
波次/「可以同時」Kahn frontier 整批 = 一波;波內排序=決定性輸出
