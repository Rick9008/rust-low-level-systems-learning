arena + index:同一招,兩個毫不相干的用途

std-only Rust · edition 2021 · 所有 code 已用 rustc 1.75 實際編譯 + 交叉驗證

一句話先分清楚

「不用指標、用 u32 / usize index 互指」這招會出現在兩個地方,考點完全不同,別混:

用途 A(並發)用途 B(單執行緒)
要解的問題lock-free 的 reclamation 地獄:pop 後這塊記憶體誰能 free?別的執行緒還握著它。Rust borrow checker 對 graph/tree 的 &mut 別名限制:兩個 node 互指在 safe Rust 幾乎寫不出。
敵人是memory allocator + 其他執行緒的時序編譯器(borrow checker)
index 幫上什麼記憶體永不還給 allocator → 沒有 use-after-free。但 index 重用讓 ABA 換個形狀回來。所有權集中在 arena(Vec<Node>),node 之間只存 index → 沒有別名、沒有 cycle leak、沒有 runtime borrow 成本。
額外機制tagged index:AtomicU64 = [generation | index](進階)generational index 防 stale handle —— 和 A 的 generation 同構
典型場景Treiber stack / MS-queue、free list、slabDSU、adjacency list、petgraph、tree 遍歷

兩者唯一的共通點,只是「機制」,不是「問題」

A 和 B 都把「pointer」換成「整數 index」,但這是手段撞在一起而已。A 解的是並發下的安全重用,B 解的是單執行緒下的別名表達力。把它們當同一件事,面試會被追問打穿(見 self-quiz 第 2 題)。

什麼時候伸手拿哪一個

  • A要寫 lock-free 結構、又不准用 crossbeam / epoch / hazard pointer → 用固定大小 arena + tagged index 把 reclamation 問題「消去」(不是解決,是繞過)。
  • B要在單執行緒建 graph / tree / union-find,又不想陷進 Rc<RefCell<Node>> 的 ownership 地獄 → 把 node 丟進 Vec,用 index 當「指標」。這是 Rust 圈做圖論的慣用解。

本頁怎麼讀

每個用途都照這個順序:naive 版 → 它的失敗模式 → 修法,概念在靜態卡先建好,再進互動 stepper。所有 Rust 都可編譯、無 // 省略 佔位。不確定的事實標 unverified。

Alock-free with arena:繞開 reclamation 地獄

① naive 版:AtomicPtr Treiber stack

先看最直白的 lock-free stack:head 是一個 AtomicPtr<Node>,push/pop 用 CAS 換 head。

可編譯 · rustc --edition 2021 --crate-type lib 通過
// Use A intro: naive AtomicPtr Treiber stack.
// Compiles and is memory-safe ONLY because it leaks (never frees).
// The moment you add Box::from_raw to reclaim, the (*head).next read in
// another thread's pop() becomes a use-after-free.
use std::sync::atomic::{AtomicPtr, Ordering};
use std::ptr;

struct Node {
    value: u32,
    next: *mut Node,
}

pub struct Stack {
    head: AtomicPtr<Node>,
}

impl Stack {
    pub fn new() -> Self {
        Stack { head: AtomicPtr::new(ptr::null_mut()) }
    }

    pub fn push(&self, value: u32) {
        let node = Box::into_raw(Box::new(Node { value, next: ptr::null_mut() }));
        loop {
            let head = self.head.load(Ordering::Acquire);
            unsafe { (*node).next = head; }
            if self
                .head
                .compare_exchange_weak(head, node, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                break;
            }
        }
    }

    pub fn pop(&self) -> Option<u32> {
        loop {
            let head = self.head.load(Ordering::Acquire);
            if head.is_null() {
                return None;
            }
            // UAF SITE (if we ever freed): another thread may have popped+freed `head`.
            let next = unsafe { (*head).next };
            if self
                .head
                .compare_exchange_weak(head, next, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                let value = unsafe { (*head).value };
                // let _ = unsafe { Box::from_raw(head) }; // <- adding this = UAF above.
                return Some(value); // we LEAK head deliberately.
            }
        }
    }
}

失敗模式:reclamation —— 到底誰能 free?

看 pop() 裡這行:let next = unsafe { (*head).next };

時序:執行緒 T1 load 到 head = P。T1 還沒讀 (*P).next,就被 preempt。此時 T2 把 P pop 掉、Box::from_raw(P) 釋放記憶體。T1 回來讀 (*P).next → 讀到已釋放的記憶體 = use-after-free。

所以上面那段 code 之所以能編譯且 memory-safe,是因為它故意 leak(pop 裡永遠不 Box::from_raw)。一旦你加上釋放,UAF 立刻出現在別的執行緒的 (*head).next。

這就是 reclamation 地獄。業界的解法(hazard pointer、epoch-based reclamation、RCU)都很重 —— crossbeam 的 epoch 就是在做這件事。本次面試不准用外部 crate,所以我們換路。

② 修法第一步:arena 把「free」消去

核心轉念:記憶體永不還給 allocator。開一塊固定大小的 Box<[Slot]>(arena),node 之間不用指標、用 u32 index 互指。pop 掉的 slot 不釋放,而是掛回一條 free list 等重用。

UAF 消失了

既然 slot 的記憶體永遠在那塊 arena 裡(從不 unmap),slots[idx].next 這個讀取永遠合法 —— 頂多讀到「邏輯上過期」的值,但不會碰到未映射記憶體。reclamation 的記憶體安全問題,被「不釋放」直接消去。

但 ABA 換個形狀回來了

記憶體安全 ≠ 邏輯正確。你把 pointer 換成 index、又重用 slot,於是「同一個 index 值」可以指向邏輯上不同的元素。一個 cache 住舊 index 的 CAS,會在 index 繞回同值時誤判成功。這就是 ABA —— 它不是記憶體問題,是「CAS 判定身份」的問題。下面用 stepper 走一遍。

③ 修法第二步:tagged index —— 讓每次重用都被看見

狀態變數 head 從「只存 index」升級成 AtomicU64 = [generation : u32 高位 | index : u32 低位]。這個 tag/generation 在每次成功 CAS 都 +1。ABA 防禦的關鍵:CAS 比對整個 64-bit,所以只要 head 被動過(哪怕 index 繞回同值),tag 已經前進,舊值的 CAS 必然失敗。

重點片段 · pack/unpack + free-list 的 tagged CAS(節錄自下方完整檔)
const NULL: u32 = u32::MAX;

#[inline]
fn pack(tag: u32, index: u32) -> u64 {
    ((tag as u64) << 32) | (index as u64)
}

#[inline]
fn unpack(v: u64) -> (u32, u32) {
    ((v >> 32) as u32, v as u32)
}

struct Slot {
    next: AtomicU32, // index of next slot, or NULL
    val: AtomicU32,  // payload kept atomic so &self mutation stays 100% safe
}

pub struct ArenaStack {
    slots: Box<[Slot]>,
    data: AtomicU64, // data stack head:  [tag | index]
    free: AtomicU64, // free list head:   [tag | index]
}

impl ArenaStack {
    pub fn with_capacity(cap: u32) -> Self {
        assert!(cap > 0 && cap < NULL);
        let mut v = Vec::with_capacity(cap as usize);
        for i in 0..cap {
            // free list initially chains 0 -> 1 -> ... -> (cap-1) -> NULL
            let next = if i + 1 < cap { i + 1 } else { NULL };
            v.push(Slot { next: AtomicU32::new(next), val: AtomicU32::new(0) });
        }
        ArenaStack {
            slots: v.into_boxed_slice(),
            data: AtomicU64::new(pack(0, NULL)), // empty stack
            free: AtomicU64::new(pack(0, 0)),    // all slots free, head = 0
        }
    }

    // Pop a free slot (Treiber pop on the free list).
    fn alloc(&self) -> Option<u32> {
        loop {
            let old = self.free.load(Ordering::Acquire);
            let (tag, idx) = unpack(old);
            if idx == NULL {
                return None; // arena exhausted -> bounded reject
            }
            let next = self.slots[idx as usize].next.load(Ordering::Relaxed);
            let new = pack(tag.wrapping_add(1), next);
            if self
                .free
                .compare_exchange_weak(old, new, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                return Some(idx);
            }
        }
    }

free list 自己也是一個 Treiber stack(alloc = pop、dealloc = push),所以它也有 ABA —— 上面 alloc 對 self.free 的 CAS 同樣掛了 tag。這不是可選項,是必須(追問 L1 會打這裡)。

完整實作(bounded lock-free stack over arena)

已編譯 + 通過 8-thread 守恆測試:8 執行緒各 push/pop 1000 次,總 pop 數精確 = 8000,無遺失/重複節點
// Use A core: bounded lock-free Treiber stack over an index arena.
// Head is AtomicU64 = [tag: u32 (high) | index: u32 (low)].
// The tag advances on every successful CAS -> defeats ABA on the head.
// Nodes are never freed; freed slots return to a free list (itself a
// tagged Treiber stack, so it has the SAME ABA and needs the SAME tag).
use std::sync::atomic::{AtomicU32, AtomicU64, Ordering};

const NULL: u32 = u32::MAX;

#[inline]
fn pack(tag: u32, index: u32) -> u64 {
    ((tag as u64) << 32) | (index as u64)
}

#[inline]
fn unpack(v: u64) -> (u32, u32) {
    ((v >> 32) as u32, v as u32)
}

struct Slot {
    next: AtomicU32, // index of next slot, or NULL
    val: AtomicU32,  // payload kept atomic so &self mutation stays 100% safe
}

pub struct ArenaStack {
    slots: Box<[Slot]>,
    data: AtomicU64, // data stack head:  [tag | index]
    free: AtomicU64, // free list head:   [tag | index]
}

impl ArenaStack {
    pub fn with_capacity(cap: u32) -> Self {
        assert!(cap > 0 && cap < NULL);
        let mut v = Vec::with_capacity(cap as usize);
        for i in 0..cap {
            // free list initially chains 0 -> 1 -> ... -> (cap-1) -> NULL
            let next = if i + 1 < cap { i + 1 } else { NULL };
            v.push(Slot { next: AtomicU32::new(next), val: AtomicU32::new(0) });
        }
        ArenaStack {
            slots: v.into_boxed_slice(),
            data: AtomicU64::new(pack(0, NULL)), // empty stack
            free: AtomicU64::new(pack(0, 0)),    // all slots free, head = 0
        }
    }

    // Pop a free slot (Treiber pop on the free list).
    fn alloc(&self) -> Option<u32> {
        loop {
            let old = self.free.load(Ordering::Acquire);
            let (tag, idx) = unpack(old);
            if idx == NULL {
                return None; // arena exhausted -> bounded reject
            }
            let next = self.slots[idx as usize].next.load(Ordering::Relaxed);
            let new = pack(tag.wrapping_add(1), next);
            if self
                .free
                .compare_exchange_weak(old, new, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                return Some(idx);
            }
        }
    }

    // Return a slot to the free list (Treiber push on the free list).
    fn dealloc(&self, idx: u32) {
        loop {
            let old = self.free.load(Ordering::Acquire);
            let (tag, head_idx) = unpack(old);
            self.slots[idx as usize].next.store(head_idx, Ordering::Relaxed);
            let new = pack(tag.wrapping_add(1), idx);
            if self
                .free
                .compare_exchange_weak(old, new, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                return;
            }
        }
    }
    // Push a value. Err(value) if the arena is full (bounded).
    pub fn push(&self, value: u32) -> Result<(), u32> {
        let idx = match self.alloc() {
            Some(i) => i,
            None => return Err(value),
        };
        self.slots[idx as usize].val.store(value, Ordering::Relaxed);
        loop {
            let old = self.data.load(Ordering::Acquire);
            let (tag, head_idx) = unpack(old);
            self.slots[idx as usize].next.store(head_idx, Ordering::Relaxed);
            let new = pack(tag.wrapping_add(1), idx);
            // Release publishes both the val store and the next store above.
            if self
                .data
                .compare_exchange_weak(old, new, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                return Ok(());
            }
        }
    }

    // Pop a value.
    pub fn pop(&self) -> Option<u32> {
        loop {
            let old = self.data.load(Ordering::Acquire);
            let (tag, idx) = unpack(old);
            if idx == NULL {
                return None;
            }
            let next = self.slots[idx as usize].next.load(Ordering::Relaxed);
            let new = pack(tag.wrapping_add(1), next);
            if self
                .data
                .compare_exchange_weak(old, new, Ordering::AcqRel, Ordering::Acquire)
                .is_ok()
            {
                let value = self.slots[idx as usize].val.load(Ordering::Relaxed);
                self.dealloc(idx); // slot reused later -> ABA is why we tag.
                return Some(value);
            }
        }
    }
}

payload 為什麼是 AtomicU32?誠實邊界

這裡把 val 設成 AtomicU32,是為了讓 &self 下的寫入100% safe(atomic 永遠可並發存取)。真實的泛型 payload T 需要 UnsafeCell<T> + 一條 unsafe 不變式:「alloc/dealloc protocol 保證同一時刻只有一個執行緒獨佔該 slot」。本檔為了「可編譯且全 safe」選了前者;正確性論證在 alloc→寫→push 這段獨佔期。

從 stepper 得到的一句話

arena 把 reclamation(記憶體安全)消去;tag 把 ABA(身份判定)消去。兩件事、兩個機制,少一個都不行。

誠實邊界(必背)

  • tag 會 wrap: generation 是 32-bit,理論上 2³² 次 CAS 後繞回。若某執行緒剛好卡住整整 2³² 次操作、且 index 又回到同值,ABA 復活。實務上機率天文數字級低,但這是真的洞(追問 L2)。
  • free list 自身的 ABA: 已在 alloc/dealloc 用 tag 擋掉,和 data stack 同一招。
  • arena 滿了: alloc 回 None → push 回 Err(value),這是 bounded-reject。要 grow(動態擴容)且維持 lock-free 極難(追問 L3)。

Bindex-based arena:繞開 borrow checker(單執行緒)

① 為什麼 safe Rust 幾乎寫不出「兩個 node 互指」

Rust 的 &mut 是獨佔的(aliasing XOR mutation)。想在 struct field 存 &mut Node 來讓兩個 node 互指,會同時撞上「獨佔別名」和「self-referential 的 lifetime 無法命名」兩道牆。

已編譯驗證會失敗 · 實際錯誤是 E0506(不是直覺以為的 E0499)
// Use B motivation: two nodes pointing to each other with &mut is
// forbidden by the borrow checker (&mut is exclusive: aliasing XOR mutation).
struct Node<'a> {
    value: i32,
    next: Option<&'a mut Node<'a>>,
}

fn main() {
    let mut a = Node { value: 1, next: None };
    let mut b = Node { value: 2, next: None };
    a.next = Some(&mut b);
    b.next = Some(&mut a); // cannot: a is already mutably borrowed via a.next
}

一旦 &mut b 被存進 a.next,b 就被獨佔借走,你連 b.next = ... 都不能寫。互指?不可能。

那 Rc<RefCell<Node>> 呢?能,但有代價

  • runtime borrow check: 每次 .borrow_mut() 都是執行期檢查,違規panic(不是編譯期擋)。
  • reference cycle 會 leak: node 互相 Rc 指 → strong count 永遠不歸零 → 記憶體洩漏。要用 Weak 打斷 cycle,心智負擔大。
  • cache 不友善: 每個 node 一次堆積配置,散在記憶體各處。

修法:所有權集中在 arena,node 只存 index

把 node 全丟進一個 Vec<Node>。node 之間不存參照、只存 usize index。於是:沒有別名問題(唯一擁有者是那個 Vec)、沒有 cycle-as-leak(index 不是 owning pointer)、沒有 runtime borrow 成本(存取就是 Vec 索引)。petgraph 核心就是這個設計 內部細節 unverified,但 index-based 是其核心。

② DSU / union-find:index 思維的極致,一個 Vec 就夠

狀態變數在此建立:parent: Vec<usize>,parent[i] = 父節點的 index,root 指向自己;rank: Vec<u8> = 樹高上界。兩個優化:path compression(find 回程把沿路每個 node 直接指向 root)+ union by rank(矮樹掛到高樹下)。

已編譯 + 對照 brute-force labeling 交叉驗證
// Use B: disjoint set union. Pure index-based, std-only, one Vec is enough.
// parent[i] = index of parent (root points to itself). rank = height upper bound.
pub struct DisjointSet {
    parent: Vec<usize>,
    rank: Vec<u8>,
}

impl DisjointSet {
    pub fn new(n: usize) -> Self {
        DisjointSet {
            parent: (0..n).collect(), // each element starts as its own root
            rank: vec![0; n],
        }
    }

    // find with path compression: every node on the path re-points to the root.
    pub fn find(&mut self, x: usize) -> usize {
        if self.parent[x] != x {
            let root = self.find(self.parent[x]); // parent[x] copied out (usize: Copy)
            self.parent[x] = root;
        }
        self.parent[x]
    }

    // union by rank: attach the shorter tree under the taller root.
    // Returns false if a and b were already in the same set.
    pub fn union(&mut self, a: usize, b: usize) -> bool {
        let ra = self.find(a);
        let rb = self.find(b);
        if ra == rb {
            return false;
        }
        if self.rank[ra] < self.rank[rb] {
            self.parent[ra] = rb;
        } else if self.rank[ra] > self.rank[rb] {
            self.parent[rb] = ra;
        } else {
            self.parent[rb] = ra;
            self.rank[ra] += 1;
        }
        true
    }

    pub fn connected(&mut self, a: usize, b: usize) -> bool {
        self.find(a) == self.find(b)
    }
}

fn main() {
    let mut d = DisjointSet::new(6);
    assert!(d.union(0, 1));
    assert!(d.union(2, 3));
    assert!(d.union(0, 2));
    assert!(!d.union(1, 3)); // already connected via 0-1-2-3
    assert!(d.connected(1, 3));
    assert!(!d.connected(1, 4));
    assert!(d.union(4, 5));
    assert!(d.union(0, 4));
    assert!(d.connected(3, 5)); // all merged now
    // brute-force cross-check against a reference labeling
    let edges = [(0usize, 1usize), (2, 3), (0, 2), (4, 5), (0, 4)];
    let mut label = [0usize, 1, 2, 3, 4, 5];
    for &(a, b) in &edges {
        let (la, lb) = (label[a], label[b]);
        for l in label.iter_mut() {
            if *l == lb { *l = la; }
        }
    }
    for i in 0..6 {
        for j in 0..6 {
            assert_eq!(d.connected(i, j), label[i] == label[j], "mismatch {} {}", i, j);
        }
    }
    println!("dsu: OK");
}

// Use B: graph on index-based adjacency list. All std-only.
use std::cmp::Reverse;
use std::collections::{BinaryHeap, VecDeque};

// BFS from start; returns visit order.
pub fn bfs(adj: &[Vec<usize>], start: usize) -> Vec<usize> {
    let mut visited = vec![false; adj.len()];
    let mut order = Vec::new();
    let mut q = VecDeque::new();
    visited[start] = true;
    q.push_back(start);
    while let Some(u) = q.pop_front() {
        order.push(u);
        for &v in &adj[u] {
            if !visited[v] {
                visited[v] = true;
                q.push_back(v);
            }
        }
    }
    order
}

// Iterative DFS from start; returns visit order.
pub fn dfs(adj: &[Vec<usize>], start: usize) -> Vec<usize> {
    let mut visited = vec![false; adj.len()];
    let mut order = Vec::new();
    let mut stack = vec![start];
    while let Some(u) = stack.pop() {
        if visited[u] {
            continue;
        }
        visited[u] = true;
        order.push(u);
        for &v in adj[u].iter().rev() {
            if !visited[v] {
                stack.push(v);
            }
        }
    }
    order
}

// Kahn's topological sort; None if the graph has a cycle.
pub fn topo_sort(adj: &[Vec<usize>]) -> Option<Vec<usize>> {
    let n = adj.len();
    let mut indeg = vec![0usize; n];
    for u in 0..n {
        for &v in &adj[u] {
            indeg[v] += 1;
        }
    }
    let mut q: VecDeque<usize> = (0..n).filter(|&u| indeg[u] == 0).collect();
    let mut order = Vec::with_capacity(n);
    while let Some(u) = q.pop_front() {
        order.push(u);
        for &v in &adj[u] {
            indeg[v] -= 1;
            if indeg[v] == 0 {
                q.push_back(v);
            }
        }
    }
    if order.len() == n { Some(order) } else { None }
}

// Dijkstra on a weighted adjacency list (v, weight). min-heap via Reverse.
pub fn dijkstra(adj: &[Vec<(usize, u64)>], start: usize) -> Vec<u64> {
    let mut dist = vec![u64::MAX; adj.len()];
    let mut heap = BinaryHeap::new();
    dist[start] = 0;
    heap.push(Reverse((0u64, start)));
    while let Some(Reverse((d, u))) = heap.pop() {
        if d > dist[u] {
            continue; // stale entry
        }
        for &(v, w) in &adj[u] {
            let nd = d.saturating_add(w);
            if nd < dist[v] {
                dist[v] = nd;
                heap.push(Reverse((nd, v)));
            }
        }
    }
    dist
}

fn main() {
    // 0->1, 0->2, 1->3, 2->3, 3->4  (a small DAG)
    let g: Vec<Vec<usize>> =
        vec![vec![1, 2], vec![3], vec![3], vec![4], vec![]];
    assert_eq!(bfs(&g, 0), vec![0, 1, 2, 3, 4]);
    assert_eq!(dfs(&g, 0), vec![0, 1, 3, 4, 2]);
    let topo = topo_sort(&g).expect("DAG has a topo order");
    // validate topo: for every edge u->v, pos[u] < pos[v]
    let mut pos = vec![0usize; g.len()];
    for (i, &u) in topo.iter().enumerate() { pos[u] = i; }
    for u in 0..g.len() {
        for &v in &g[u] {
            assert!(pos[u] < pos[v], "topo violated {}->{}", u, v);
        }
    }
    // cycle -> None
    let cyc: Vec<Vec<usize>> = vec![vec![1], vec![2], vec![0]];
    assert!(topo_sort(&cyc).is_none());

    // Dijkstra: 0-(1)->1, 0-(4)->2, 1-(2)->2, 1-(7)->3, 2-(1)->3
    let wg: Vec<Vec<(usize, u64)>> = vec![
        vec![(1, 1), (2, 4)],
        vec![(2, 2), (3, 7)],
        vec![(3, 1)],
        vec![],
    ];
    let dist = dijkstra(&wg, 0);
    assert_eq!(dist, vec![0, 1, 3, 4]); // 0->1->2->3 = 1+2+1 = 4
    println!("graph: OK");
}

兩個 std 慣用點

  • BinaryHeap 是 max-heap,要 min-heap 就包 Reverse。Dijkstra 靠這個。
  • Dijkstra 的 stale entry:pop 出來若 d > dist[u] 直接 skip —— 這是「lazy deletion」,避免 std BinaryHeap 沒有 decrease-key 的問題。saturating_add 防 u64 溢位。

④ tree:同樣 Vec<Node> + child indices

tree 是 graph 的特例。parent link 只是 Option<usize> —— 不需要 Weak(index 不是 owning),不會 leak cycle,遍歷就是遞迴索引,沒有 .borrow() 執行期檢查。對照 Rc<RefCell> 版本,index 版順很多。

// Use B: tree as an arena. Parent link is just Option<usize> -> no Weak,
// no reference cycle to leak, no runtime borrow check. Access = Vec index.
pub struct TreeArena {
    nodes: Vec<TreeNode>,
}

pub struct TreeNode {
    pub value: i32,
    pub parent: Option<usize>,
    pub children: Vec<usize>,
}

impl TreeArena {
    pub fn new() -> Self {
        TreeArena { nodes: Vec::new() }
    }

    // Insert a node; wire it into its parent's child list. Returns its index.
    pub fn add(&mut self, value: i32, parent: Option<usize>) -> usize {
        let id = self.nodes.len();
        self.nodes.push(TreeNode { value, parent, children: Vec::new() });
        if let Some(p) = parent {
            self.nodes[p].children.push(id);
        }
        id
    }

    // Recursive subtree sum -- trivial with indices, no borrow gymnastics.
    pub fn subtree_sum(&self, id: usize) -> i32 {
        let node = &self.nodes[id];
        let mut total = node.value;
        for &c in &node.children {
            total += self.subtree_sum(c);
        }
        total
    }

    // Depth via parent chain (walk up).
    pub fn depth(&self, mut id: usize) -> usize {
        let mut d = 0;
        while let Some(p) = self.nodes[id].parent {
            d += 1;
            id = p;
        }
        d
    }
}

fn main() {
    let mut t = TreeArena::new();
    let root = t.add(1, None);
    let a = t.add(2, Some(root));
    let b = t.add(3, Some(root));
    let _c = t.add(4, Some(a));
    let _d = t.add(5, Some(a));
    assert_eq!(t.subtree_sum(root), 1 + 2 + 3 + 4 + 5);
    assert_eq!(t.subtree_sum(a), 2 + 4 + 5);
    assert_eq!(t.subtree_sum(b), 3);
    assert_eq!(t.depth(root), 0);
    assert_eq!(t.depth(a), 1);
    assert_eq!(t.depth(_c), 2);
    println!("tree: OK");
}

選擇準則

整張圖同一個生命週期、要 cache locality、想躲 Rc 開銷與 cycle leak → index。node 需要異質生命週期、結構要能隨 Rc 歸零自動收縮 → Rc<RefCell>。面試絕大多數圖論題,答案是 index。

常見面試追問(至少 3 層深)

L4 modal = medium 題 + follow-up。這裡把 escalation 排成階梯,每層都是上一層答對後會被追問的。

Alock-free 這條線

L1 ── 「你的 tag 擋住了 data stack 的 ABA。free list 呢?」

free list 本身就是另一個 Treiber stack(alloc=pop、dealloc=push),同樣有 ABA,要掛同樣的 tag。本檔 self.free 的 CAS 已經是 tagged。若只 tag data stack、不 tag free list,你會在 alloc 撞到一模一樣的 stale-CAS-成功。這題在測你有沒有意識到「同一結構重複出現、同一漏洞就重複出現」。

L1' ── 「你 stepper 假設 allocator 把剛 free 的 slot 交回來。可是嚴格 LIFO free list 的重用順序是被序列化的,那 ABA 還會發生嗎?」

好問題,而且很微妙。嚴格 LIFO free list 下,T1 正在操作的 head node 是最先被 free 的,所以會最後才被重用;等它終於被重用時,中間那個 node 早已被 push 回堆疊(這才騰出 free list 的位置),於是 A.next 通常又指回一個合法的在堆疊 node。這讓最單純的 ABA 反例難以構造。

但別依賴這個脆弱推理。它一崩就崩:(i) 多條 free list / size class;(ii) 你把 index 暴露給外部持有者、跨操作 cache(就是 generational index 的場景);(iii) queue 這類 head/tail 重用方式不同的結構;(iv) 任何非 LIFO 的重用策略。tag 的價值就是讓正確性不依賴「allocator 怎麼重用」這種推理 —— 動過就 fail,一律成立。這是穩健的工程答案。

L2 ── 「tag 是 32-bit,會 wrap。什麼情況下 wrap 讓 ABA 復活?」

某執行緒在 CAS 前被凍結,期間其他執行緒對同一個 atomic 做了剛好 2³² 次成功 CAS,讓 tag 繞回原值,且 index 也回到同值 → 凍結的執行緒 CAS 誤成功。實務上 2³² 次操作 + 執行緒剛好卡那麼久,機率天文級低。緩解:(a) 用更寬的 tag —— 但 std 沒有穩定的 AtomicU128 unverified,std 目前無 128-bit atomic 的可攜保證,所以純 std 就是接受 32-bit tag;(b) 若 index 用不到滿 32-bit,可挪幾個 bit 給 tag。誠實講:純 std-only 下這是個可接受但真實存在的洞。

L3 ── 「為什麼 arena 要 grow(動態擴容)且維持 lock-free 這麼難?走一遍哪裡爆。」

grow 要配置新的後備儲存、把舊資料搬過去。問題:此刻可能有讀者正握著舊 store 的 index、或正在 CAS 中。你得原子地換掉整塊 backing store,同時協調這些讀者 —— 這正是你一開始想躲掉的 reclamation 問題(舊 store 何時能安全釋放?)又回來了。可行路線是加一層 indirection:分段儲存(Vec<segment>,只 append 新 segment、舊 segment 位址不動),或 RCU 式換 store + epoch 回收舊塊。所以面試給的正解通常是「bounded arena + 滿了就 reject」;要 unbounded 就得上 segmented 或 epoch,而後者已超出 std-only。

Bgraph/tree 這條線

L1 ── 「Rc<RefCell> 也能做圖。你什麼時候真的會選它而不是 index?」

當 node 需要異質生命週期(有的活得比 arena 久、有的要提早釋放)、或你要圖結構隨引用歸零自動收縮清理時,選 Rc<RefCell>。index 版的前提是「整張圖同生共死」:一起 build、一起用、一起 drop。若你的 use case 會頻繁刪 node 且要立刻回收記憶體,index 版要嘛留 tombstone、要嘛 swap-remove 打亂 index,兩者都比 Rc 的自動清理麻煩。

L2' ── 「index-based 有個 Rc<RefCell> 沒有的 footgun。是什麼?production library 怎麼修?」

stale / dangling index:你刪掉一個 node,它的 index 現在要嘛越界(panic)、要嘛(若用 swap-remove)指到另一個 node —— 型別系統不會擋,你拿到一個「看起來合法、其實指錯」的 index。Rc 天然不會:Rc 沒了就是沒了。

production 解法:generational index(如 slotmap / generational-arena crate 名稱 unverified)。index 變成 [slot | generation],slot 每次重用 generation++,存取時比對 generation → 舊 handle 驗證失敗。注意這跟用途 A 的 tagged index 是同一個機制 —— 都是「用 generation 讓重用被觀察到」。

L3' ── 「你說 generational index。但 generation 也是有限 bit,跟 ABA 的 tag wrap 是同一個問題嗎?」

是,一模一樣。有限的 generation counter 會 wrap,一個 stale handle 理論上可以在 slot 被重用剛好 2ᵏ 次後、驗證通過對到重用的 slot。32/64-bit generation 下機率天文級低,但這是和 ABA tag wrap 完全同構的洞。這題把 A 和 B 綁在一起:兩邊都用有限 generation 換「重用可觀察」,也就都繼承同一個 wrap 邊界。答得出這層,代表你看穿了「index 只是機制」。

跨界追問

「A 和 B 都用整數 index 取代 pointer。它們在解同一個問題嗎?」

不是。A 解並發下的安全重用(在其他執行緒 + allocator 的時序中,重用一塊記憶體而不 UAF);它的敵人是 memory allocator 和時序。B 解單執行緒下的別名表達力(在 borrow checker 底下表達 shared/mutable 的圖結構);它的敵人是編譯器。共用的「index 取代 pointer」只是機制撞在一起,不是問題相同。把兩者混為一談,就是這題要抓的。

Self-quiz(5 題,答案摺疊)

先自己答完再展開。這幾題涵蓋兩個用途、把它們綁在一起,並包含指定必考題。

Q1 ── arena 已經繞過 reclamation(永不 free → 沒 UAF),那 ABA 為什麼沒消失?

因為 arena 只解掉記憶體安全(那塊記憶體從不 unmap,所以讀 slots[idx].next 永遠合法)。ABA 是另一個層次的問題:它是「CAS 用什麼判定身份」的問題。你把 pointer 換成 index、又重用 slot,於是「同一個 index 值」可以指向邏輯上不同的元素。一個 cache 住舊 index 的 CAS,會在 index 繞回同值時誤判成功 → 結構被破壞。記憶體安全和邏輯正確是兩回事;arena 給你前者,tag(讓每次重用被觀察到)才給你後者。

Q2 ── 用途 A 與用途 B 都用 index 互指,但它們解的是兩個完全不同的問題。分別是什麼?

用途 A(並發):解 lock-free 的安全重用 / reclamation。在其他執行緒 + allocator 的時序下,重用一塊記憶體而不造成 use-after-free。敵人是 memory allocator 和執行緒時序。機制:固定 arena(永不 free 消去 UAF)+ tagged index(消去 ABA)。

用途 B(單執行緒):解 borrow checker 的別名表達力。在 &mut 獨佔規則下,表達「兩個 node 互指」這種 shared/mutable 圖結構。敵人是編譯器。機制:所有權集中在 Vec<Node>,node 間只存 index(消去別名、cycle leak、runtime borrow)。

「用 index 取代 pointer」是共用的機制,但兩邊要解的問題毫不相干。

Q3 ── 為什麼 graph 用 Vec<index> 而不用 Rc<RefCell<Node>>?各自的代價?

用 index 的理由 / 好處:所有權集中在 arena → 沒有別名問題;index 不是 owning pointer → 圖有 cycle 也不會 leak(Rc 版 cycle 會 leak,得用 Weak 打斷);存取是 Vec 索引 → 編譯期靜態、沒有 .borrow() 的執行期檢查與 panic 風險;連續記憶體 → cache 友善。

index 的代價:index 是「未檢查的指標」—— 可能 dangle、越界(panic)、或(swap-remove 後)指到別的 node,型別系統不擋。整張圖傾向同生共死,不利頻繁刪 node 即時回收。

Rc<RefCell> 的代價:runtime borrow check(違規 panic 不是編譯期擋)、cycle leak 要 Weak、堆積配置 cache 不友善。它的好處:node 可異質生命週期、可隨引用歸零自動收縮清理。

Q4 ── tagged index 是 [generation | index] 的 64-bit。generation 有限、會 wrap。這個 wrap 在什麼情況讓 ABA 復活?為什麼實務上通常可接受?

復活條件:某執行緒在 CAS 之前被凍結,期間其他執行緒對同一個 atomic 做了剛好 2³²(32-bit generation)次成功 CAS,使 generation 繞回原值,並且 index 也回到同一值。此時凍結執行緒帶著舊的 [gen|idx] 做 CAS,會誤判成功。

為何可接受:要湊齊「同一 atomic 恰好 2³² 次操作」+「該執行緒剛好卡住這麼久」+「index 又回同值」,機率是天文數字級。純 std-only 下沒有可攜的更寬 atomic unverified,所以通常就接受 32-bit generation;若 index 用不滿 32-bit,可挪 bit 加寬 generation 進一步壓低機率。誠實說:這是個真實但實務上可忽略的洞。

Q5 ── index-based arena 有個 Rc<RefCell> 沒有的 footgun(stale / dangling index)。它是什麼?production library 怎麼修?這跟用途 A 有什麼關係?

footgun:刪掉一個 node 後,它的 index 要嘛越界(存取 panic)、要嘛(swap-remove)指到另一個 node —— 一個「看起來合法、實則指錯」的 index,型別系統不擋。Rc 天然沒這問題(Rc 沒了就是沒了)。

修法:generational index。index 變成 [slot | generation],slot 每次重用 generation++,存取時比對 generation,舊 handle 驗證失敗即拒絕(slotmap / generational-arena 這類 crate 名稱 unverified)。

跟用途 A 的關係:這跟 A 的 tagged index 是同一個機制 —— 都是用 generation 讓「slot 被重用」變得可觀察。也因此兩邊都繼承同一個 generation wrap 邊界(見 Q4)。這正是「index 只是機制、問題各異,但機制的性質共享」的最好例證。
