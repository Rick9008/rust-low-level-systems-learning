epoll:訂閱、監聽、退訂

epoll 是 kernel 裡的一份訂閱服務:你用 epoll_ctl 管理「我關心哪些 fd 的哪些事」,用 epoll_wait 睡著等信。所有 flag 的差異都落在三個問題上:這是事件還是模式?要不要自己訂?什麼時候會再叫你?

心智模型

一張興趣表 + 一條就緒佇列

你的 event loop

單執行緒,迴圈:
wait → dispatch → 處理

⇄epoll_ctl 訂閱/改訂/退訂
epoll_wait 收信
epoll instance(本身也是個 fd)

Interest list:fd → 遮罩 + token(你訂了什麼)

Ready list:已就緒的事件排隊等你收——wait 只是把它搬進你的 buffer
←kernel 在 IRQ /
協定棧層面盯著
被監看的 fds

sockets、listener、eventfd、timerfd、pipe……任何支援 poll 的東西

重點:wait 的成本是 O(就緒數),不是 O(訂閱數)——這就是它贏過 select/poll(每次呼叫都要重新掃全表)的原因,也是「3000 條連線一條 thread」成立的前提。

最小 event loop 骨架

let ep = Epoll::new()?;
ep.add(listener.as_raw_fd(), EPOLLIN, LISTENER)?;   // 訂閱:listener 可讀 = 有連線可 accept

// buf:EpollEvent 陣列,長度 = 一輪最多收幾件
loop {
    let n = ep.wait(&mut buf, None)?;               // 睡著等;EINTR 已在 wait 裡重試
    for ev in &buf[..n] {
        if ev.events & (EPOLLERR | EPOLLHUP) != 0 {
            // 先處理錯誤——這兩個免訂閱也會回報,漏接 = 死連線永遠掛著
        }
        match ev.data {                              // token 原樣帶回
            LISTENER => { /* accept → ep.add(conn_fd, EPOLLIN, new_token) */ }
            t => { /* 用 t 找回連線;LT 讀一輪即可,ET 必須讀到 EAGAIN */ }
        }
    }
}
flags

三族 flag:事件、免訂事件、模式開關

遮罩是 u32 位元 OR。分族之後就不用背了——問自己「它是發生的事,還是通知的方式?」

族 1 · 興趣/就緒事件(訂閱時要、回報時給)

flag值意思什麼時候用
EPOLLIN0x001可讀:socket 有資料、listener 有連線可 accept、pipe/eventfd 有東西幾乎永遠訂著(除了 backpressure 關水龍頭時)
EPOLLOUT0x004可寫:send buffer 有空間了只在欠帳時掛:write 吃了 EAGAIN 才加,還清就拿掉
EPOLLRDHUP0x2000對端關了寫端(half-close):「不再送了」但你還能回寫想區分「對端說完了」和「還在等資料」時
EPOLLPRI0x002帶外資料(TCP urgent)幾乎沒人用;面試提一句就好

族 2 · 免訂閱、只出現在回報(kernel 永遠幫你盯)

flag值意思不處理的下場
EPOLLERR0x008fd 出錯(例:收到 RST、pipe 讀端全關你還在寫)死連線永遠掛在表上吃資源——dispatch 第一步永遠先檢查這兩個 bit
EPOLLHUP0x010掛斷:雙向都關了

族 3 · 模式開關(不是事件,是「怎麼通知你」)

flag值意思代價/義務
(不加 = LT)—level-triggered(預設):條件還成立,每次 wait 都叫你寬容:這輪沒讀完,下輪還會叫
EPOLLET1<<31edge-triggered:只在「變成就緒」那一刻叫一次義務:必須讀/寫到 EAGAIN,否則剩下的資料永遠沒人叫你(見下圖)
EPOLLONESHOT1<<30叫一次後自動 disarm(訂閱還在,遮罩清成 0)要再收信得 MOD 重新武裝;多執行緒 loop 用它防同一 fd 被兩條 thread 同時處理
EPOLLEXCLUSIVE1<<28多個 epoll 掛同一 listener 時只叫醒一個防 thundering herd(accept 風暴);單 loop 用不到

完整清單還有 EPOLLWAKEUP(電源管理)和 EPOLLRDNORM 等 poll 相容別名——知道存在即可。repo 只定義面試需要的 8 個(reference/src/epoll_sys.rs:52-61)。

實戰

三個訂閱管理的招式

讀端 · 關水龍頭
backpressure = MOD 掉 EPOLLIN

下游塞住時:modify(fd, mask 去掉 EPOLLIN, token) → 你不讀 → rcv buffer 積滿 → TCP 收窗縮到 0 → 對端 send() 塞住。backpressure 沿著 TCP flow control 免費傳回 producer;消化完再 MOD 回來。

這是 clarify 五問「掉不掉」的 TCP 版 full policy:不掉資料、讓上游塞住。

寫端 · 欠帳才掛
EPOLLOUT 是債權人,不是常駐嘉賓

write 吃到 EAGAIN → 緩存沒寫完的 + MOD 加上 EPOLLOUT → 可寫事件來了補寫 → 還清後把 EPOLLOUT 拿掉。

忘記拿掉的下場(LT):send buffer 幾乎永遠有空間 → 每輪 wait 都叫你 → busy loop 空轉。詳見 docs/tcp_echo.md 的欠帳狀態機。

退訂 · 暗坑
DEL 之後,舊事件還在你手上

delete(fd) + close 之後:這輪 wait 已經搬進 buf 的事件裡可能還有那條連線的;而 fd 號碼會立刻被新連線重用 → 舊事件打到新連線。

解法:token 不放裸 fd,放 fd + generation,dispatch 時對表驗票。這正是彩排 e2(fd_registry)整題的梗——JD 的 event registry sleeper。

地雷 · 型別
libc 的 EPOLLET 是負數

libc 常數是 i32,而 EPOLLET = 0x80000000 = -2147483648;跟 events: u32 欄位混用必須 as u32(docs/epoll_libc.md:61)。repo 自家 const 直接定成 u32,沒這個坑。

面試日提醒:pad 上不手搓 FFI——3 行 Poller trait stub(Abstract the Noise),一句「底層是 epoll,data 的 u64 就是我的 token」。
