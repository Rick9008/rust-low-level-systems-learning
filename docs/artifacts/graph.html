BFS 和 DFS 的程式碼幾乎逐字相同——差別只有一個:前緣放在佇列還是堆疊。 Kahn 換成 in-degree 陣列,Dijkstra 換成一個堆。 四個演算法,一份骨架,容器決定一切。

1 · 圖就是 Vec<Vec<(usize, u64)>>

adj[u] 是一條 Vec,裝著 (鄰居, 邊權)。節點是 dense id 0..n ——外部實體(字串、IP)先過一層 HashMap 映射再進來,把「識別」和「演算法」切開。 節點的 payload、邊的名字都不進 Graph:圖只管拓撲,屬性用平行陣列外掛。

表示法空間走鄰居問「u→v 有邊嗎」什麼時候用
Vec<Vec<(usize, u64)>> O(V+E) O(deg) O(deg) 稀疏圖(E 遠小於 V^2)——現實網路幾乎都是
Vec<Vec<bool>>(matrix) O(V^2) O(V) O(1) dense 圖,或邊查詢是熱路徑

無向圖 add_edge(u, v, w) 存兩份(adj[u] 和 adj[v] 各一)。 用空間換掉「遍歷時還要判方向」的分支。下面的示範圖是有向的——topo 和 Dijkstra 都需要方向。

3 · BFS 與 DFS:只有一行不一樣

  

    把兩份程式碼疊在一起看。變數名不同、容器型別不同,骨架一模一樣:
    pop 一個 → 掃它的鄰居 → 沒看過的丟進容器。
    差別在紅色那兩行——從哪一端拿。
  

  

    

      
BFS — VecDeque(FIFO)

      
let mut q = VecDeque::new();while let Some(u) = q.pop_front() {    for &(v, _) in &adj[u] {        if dist[v].is_none() {            dist[v] = Some(dist[u].unwrap() + 1);            q.push_back(v);        }    }}

    

    

      
DFS — Vec(LIFO)

      
let mut st = vec![src];while let Some(u) = st.pop() {    if visited[u] { continue; }    visited[u] = true;    order.push(u);    for &(v, _) in adj[u].iter().rev() {        if !visited[v] { st.push(v); }    }}

    

  

  

    兩個實作上的細節,面試會被追問:
  

  
    
    
  • BFS 在「入隊時」標記,不是出隊時。出隊才標記的話,同一個節點會被多條邊各推一次,
      佇列最壞膨脹到 O(E)。這一行決定了 BFS 是不是真的 O(V+E)。
    • 
    
  • DFS 在「彈出時」去重。一個節點可能被多條路徑推進 stack(示範圖裡的節點 5 就被推了兩次),
      所以 pop 出來第一件事是 if visited[u] { continue; }。
      在 stepper 裡把 DFS 跑到底,你會看到那個重複的 5 被彈出來然後丟掉。
    • 
    
  • 鄰居要反向 push,迭代版的前序才會跟遞迴版一致(後 push 的先 pop)。
    • 
    
  • 用迭代版而不是遞迴版的理由:遞迴深度 = 最長路徑。1e6 個節點的鏈會爆 call stack
      (Rust main thread 預設 8MB,spawn 出來的只有 2MB)。顯式 stack 開在 heap 上,沒有這個上限。
    • 
  






  
4 · Kahn:cycle 偵測是免費附贈的

  

    Kahn 的前緣容器是「in-degree 已經歸零的節點」——所有前置條件都清掉了,現在可以做了。
    每 pop 一個節點就把它的鄰居 in-degree 減一;減到 0 就入隊。
    輸出天然是拓撲序,因為一個節點只會在它所有前驅都出來之後才進隊。
  

  

    現在是關鍵:環上的節點,in-degree 永遠不會歸零——它們互相是對方的前置條件。
    所以佇列會提早空掉,order 湊不滿 n。
  

  
(order.len() == n).then_some(order)   // 湊不滿 ⇒ None ⇒ 有環

  

    去上面按「加 back-edge 6→3」再跑一次 Kahn:輸出只吐得出 3 個節點(共 8 個)就卡死。
    卡住的不只是環上的 3、4、6——連環下游的 5、7 也一起卡住(它們永遠等不到前驅)。
    所以「輸出長度 < n」只告訴你有環,不告訴你環在哪。要定位環得另外做(DFS 三色標記 / Tarjan SCC)。
  

  

    DFS 後序反轉也能得到拓撲序,但那條路要偵測環得維護三色標記(白/灰/黑),
    面試現場容易寫錯灰色的判斷。Kahn 只有一個 indeg 陣列和一個佇列,
    而且 cycle 偵測是順便的——同樣 O(V+E),寫錯的機會少一半。
  






  
5 · Dijkstra:Reverse、懶刪除、以及負邊

  

    Rust 的 BinaryHeap 是 max-heap。Dijkstra 要每次拿出「目前 tentative 距離最小」的節點,
    所以要把比較反過來——Reverse 就是幹這個的:
  

  
let mut heap = BinaryHeap::new();          // max-heapheap.push(Reverse((dist, node)));          // Reverse ⇒ 比較反轉 ⇒ 拿出來的是最小while let Some(Reverse((d, u))) = heap.pop() { ... }

  

    (dist, node) 這個 tuple 的順序不是隨便排的:tuple 的 Ord 是字典序,
    先比第一個欄位。dist 必須放前面,不然你排的是 node id。
  


  
懶刪除(lazy deletion)——這題是分水嶺

  

    課本的 Dijkstra 用 decrease-key:找到更短的路徑時,就地把堆裡那個節點的 key 調小。
    std::collections::BinaryHeap 沒有 decrease-key——它連「節點 u 在堆的哪個位置」都不知道。
    要有 decrease-key,你得自己寫一個帶 pos[] 索引的堆,每次 sift 都要同步更新索引。
  

  

    標準解法是不刪:鬆弛成功就再 push 一筆新的,舊的那筆留在堆裡爛掉。
    彈出來的時候檢查一次——
  

  
while let Some(Reverse((d, u))) = heap.pop() {    if dist[u].is_some_and(|best| d > best) { continue; }  // stale,丟掉    // ... 走 u 的鄰居}

  

    d > dist[u] 表示這筆條目在入堆之後,dist[u] 又被別的路徑改小了 ⇒ 這筆過期了 ⇒ 直接 continue。
    在上面的 stepper 裡跑 Dijkstra 到底,你會看到三次 stale pop 被跳過(紅色那幾格):
    (4, 1)、(6, 4)、(9, 5)。這是絕大多數人手寫時會漏掉的一行——
    漏了不會 panic,只會多做一次鬆弛(通常結果還是對的,但複雜度證明破了)。
  

  

    代價:堆裡最多 O(E) 筆條目(每條邊最多推一次),所以是 O((V+E) log E),
    而不是索引堆的 O((V+E) log V)。因為 E 小於 V^2,log E < 2 log V ——
    常數級的差距,換掉一整個自訂資料結構。面試講得出這個取捨,比寫出 decrease-key 更值錢。
  


  
負邊:Dijkstra 直接是錯的

  

    Dijkstra 的正確性建立在一個貪心不變式上:從堆裡彈出的節點,它的 dist 就定案了。
    這句話只有在「邊權非負」時才成立——因為往後走只會讓距離變大,不可能繞遠路反而更短。
  

  

    有一條負邊,這個不變式就垮了,Dijkstra 會給出錯的答案(不是慢,是錯)。
    這也是簽名寫 w: u64 而不是 i64 的原因:用型別把前提釘死。
    真的有負邊 ⇒ Bellman-Ford(O(VE),還順便偵測負環);全點對 ⇒ Johnson 或 Floyd-Warshall。
  

  

    順帶一提,堆的內部陣列不是排序好的——binary heap 只保證根是最小(這裡是被 Reverse 反轉過的最小)。
    上面 stepper 顯示的堆內容是真的堆陣列,你會看到它長得很亂,但 index 0 永遠是下一個要彈出的。
  






  
6 · 四件套的複雜度

  

    

      
        
演算法前緣容器時間空間前提 / 限制

      
      
        

          BFS
          VecDeque<usize>
          O(V+E)
          O(V)
          只給邊數最短路。有權重就不能用(除非全部等權)
        

        

          DFS(迭代)
          Vec<usize>
          O(V+E)
          O(V)
          不給最短路。用途是連通性、環偵測、SCC、後序
        

        

          Kahn topo
          VecDeque + indeg[]
          O(V+E)
          O(V)
          只對有向圖有意義。順便偵測環
        

        

          Dijkstra
          BinaryHeap<Reverse<(u64, usize)>>
          O((V+E) log E)
          O(V+E)
          邊權必須非負。堆裡有 O(E) 筆懶刪除條目
        

      
    

  

  

    Production 對照:Rust 生態是 petgraph(泛型圖 + 一整套演算法)。
    真的大圖會把 Vec<Vec<_>> 換成 CSR(compressed sparse row):
    兩條扁平陣列 offsets[] 和 targets[],消掉第二層指標跳躍,
    鄰居在記憶體裡連續 ⇒ prefetcher 幫你把整段拉進 cache。
    原理跟 arena_lockfree 的 arena 一樣:把散落 heap 的東西攤平成連續陣列。
