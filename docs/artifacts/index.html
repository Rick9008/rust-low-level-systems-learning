兩種用法

互動模組是可以操作的機制,不是圖。刻意把每個模組最容易錯的那一步做成按鈕: 把 Acquire 降成 Relaxed、把 while 換成 if、 ET 模式下只讀一半就停手、拔掉 generation tag——然後看它當場壞給你看。

計時彩排是面試 prompt 風格的題目:只給場景、contract、規模,不給做法。 照 45 分鐘 protocol 跑,測試自己寫在同一個檔案底部——重演 CoderPad 的單檔條件。

先讀哪些:面試優先級

cost model 速查

面試公式:先給 Big-O,再給常數,再指出規模轉折點。講數量級就夠,講得比這精確反而可疑。

操作數量級面試用途
atomic load/store(x86,無競爭)~1 ns編出來就是 mov;acquire/release 在 x86 免費
Mutex lock/unlock(無競爭)~20 ns純 userspace CAS,沒有 syscall
Mutex(有競爭)~1–10 µsfutex syscall + context switch——貴 100× 的來源
context switch~1–5 µs外加 cache 汙染的隱性成本
thread spawn~數十 µsstack 預設 2 MiB;一萬條 = 20 GB 虛擬位址
poll O(N) vs epoll O(ready)1000×N=10,000、ready=10:每次 wakeup 掃 10,000 vs 碰 10

並發模型轉折點:thread-per-conn(百級連線)→ acceptor + 固定 pool(需並發上限)→ epoll / tokio(萬級 IO-bound)→ CPU-bound 任務凍住 loop 就 offload; readiness(epoll)碰到 regular file 永遠 ready → completion(io_uring)。
