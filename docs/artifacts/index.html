互動教材

19 個互動模組、1 間 clarify 決策室、13 份深讀教材(html_p:追問鏈 + self-quiz)、10 頁問答圖解、4 頁彩排題教學(Q4–Q7),加 9 題計時彩排。測試證明程式碼是對的,卻建立不了直覺、也建立不了臨場反射—— 互動頁讓你親手把機制弄壞再看它為什麼壞;彩排讓你在 45 分鐘裡把它重演一次。

兩種用法

互動模組是可以操作的機制,不是圖。刻意把每個模組最容易錯的那一步做成按鈕: 把 Acquire 降成 Relaxed、把 while 換成 if、 ET 模式下只讀一半就停手、拔掉 generation tag——然後看它當場壞給你看。

計時彩排是面試 prompt 風格的題目:只給場景、contract、規模,不給做法。 照 45 分鐘 protocol 跑,測試自己寫在同一個檔案底部——重演 CoderPad 的單檔條件。

先讀哪些:面試優先級

面試在 CoderPad:單檔、固定 crate 清單——實測 Rust 1.92(2024 Edition), 有 tokio、無 libc / mio。自寫 unsafe extern "C" 綁 raw syscall 連得上, epoll 技術上做得到;但 45 分鐘單檔手搓 epoll loop 是壞賭注、tokio 又在清單裡—— 所以 epoll 一族分在 deep-dive:拿來答 readiness model / event loop 概念題、 看懂 tokio 底下發生什麼,讀懂即可,不手搓。場上遇到 epoll,三行 Poller trait stub 帶過(Abstract the Noise)——不掏 FFI。

下面的模組不再按 stage 排,改按面試優先級。難度順序(mutex → 資料結構 → atomics → executor → event loop) 仍在 git log --oneline --reverse。★ = 有 challenges/ 空白手搓版。 第 1 課 iter_mutate 與第 8 課 fd_registry 是文字/程式教材 (docs/iter_mutate.md、docs/fd_registry.md),無互動頁。

大題定界:escalation ladder

Prompt 看起來像「build a runtime」(pool + executor + reactor 全都要)時,考的是定界,不是手速。 開場 30 秒宣告切法,然後照階梯走——一顆用寫的,其餘用講的:

2 · ~3 分講多 task:run queue + Arc<Task>,wake = 把自己 push 回 queue——thread pool 骨架換 payload
3 · ~3 分講真 IO:reactor thread + epoll + interest table;std 沒有多路等待原語,這層是 tokio(mio→epoll)接手

cost model 速查

面試公式:先給 Big-O,再給常數,再指出規模轉折點。講數量級就夠,講得比這精確反而可疑。

操作數量級面試用途
atomic load/store(x86,無競爭)~1 ns編出來就是 mov;acquire/release 在 x86 免費
Mutex lock/unlock(無競爭)~20 ns純 userspace CAS,沒有 syscall
Mutex(有競爭)~1–10 µsfutex syscall + context switch——貴 100× 的來源
context switch~1–5 µs外加 cache 汙染的隱性成本
thread spawn~數十 µsstack 預設 2 MiB;一萬條 = 20 GB 虛擬位址
poll O(N) vs epoll O(ready)1000×N=10,000、ready=10:每次 wakeup 掃 10,000 vs 碰 10

並發模型轉折點:thread-per-conn(百級連線)→ acceptor + 固定 pool(需並發上限)→ epoll / tokio(萬級 IO-bound)→ CPU-bound 任務凍住 loop 就 offload; readiness(epoll)碰到 regular file 永遠 ready → completion(io_uring)。
