Unbounded × lock-free:刻意空白的那一格

佇列選型是一張 2×2 的表,repo 給了三格可執行的教材,第四格刻意留白。這頁講清楚:那格裡住著什麼(Michael–Scott、SegQueue,認臉即可)、為什麼它是沼澤(回收問題)、以及它唯一堂堂正正的用途——executor 的 run queue。

認臉:Michael–Scott queue(經典 unbounded lock-free MPMC)

形狀:單向鏈表 + 一個 dummy 節點。head 指 dummy(出隊端)、tail 指最後一個節點(入隊端),兩端各自用 CAS 推進——所以多生產者多消費者都行,而且鏈表要多長有多長 = unbounded。

三個認臉要點(面試講這些就夠,不用會默寫):

  • Dummy 節點:讓「空佇列」和「非空」共用同一套不變量,head 永遠有東西可指。
  • 入隊是兩步 CAS:先 CAS tail.next 掛新節點,再 CAS 推進 tail——第二步可能被別人「幫忙完成」(helping,lock-free 演算法的招牌動作)。
  • 真正的難點不是佇列,是回收:出隊的節點何時能 free?上圖那個窗口。順帶:如果記憶體被 allocator 重用,head 的 CAS 還會撞 ABA——同一坨問題的另一張臉。

SegQueue:工程化的折衷形狀

crossbeam 的 SegQueue = 「固定大小區塊」串成的鏈表:每個 segment 內部像一段小 ring(index 推進,快路徑無配置),segment 滿了才配置下一塊。配置成本被攤薄(一次配置 32 格),但 segment 本身仍要回收 → 底下還是 epoch。一句記憶法:SegQueue = spsc_ring 的快路徑 × Michael–Scott 的鏈式外殼。鄰居還有一個名字認一下就好:Chase–Lev deque(work-stealing 的那個,escalation ladder 第 4 階的「何時要 work-stealing」指的就是它)。

唯一堂堂正正的用途:executor 的 run queue

Unbounded 合法需要兩個前提同時成立,而 run queue 剛好都中:

  1. Producer 不可阻塞、不可丟:wake() 從任何執行緒、任何 context 來,不能 block;丟一個 wakeup = task 永遠睡死。「滿了怎麼辦」的三個選項全部非法 → 只剩 unbounded。
  2. 量被外部不變量鎖住:scheduled bit 保證一個 task 同時最多在隊裡一次 → 隊長 ≤ task 總數。名義 unbounded,界在別處。

同族:std::sync::mpsc::channel()(unbounded,內部鏈式 lock-free)vs sync_channel(n)(bounded)——std 用兩個名字把這對分開,pad 上提這句白拿一分。

面試三句

不主動開這格:「unbounded」對「界在哪」交白卷、「lock-free」沒有 p99.9 撐腰、「MPMC」範圍爆炸——三重紅旗。光譜心法:停在需求要的那站。
被追問「做成 unbounded 呢?」(30 秒版):“Linked segments of fixed-size rings — amortize allocation, keep the fast path ring-like; that's crossbeam's SegQueue shape. The hard part isn't the queue, it's reclamation — when is a node safe to free while another thread may still hold it? That's epoch-based territory, so in production I'd take crossbeam rather than hand-roll it.” 價值在指名真正的難點(回收),然後選擇不爬。
Executor 題的加分句:“The run queue is the one place I'd go unbounded: wake() can't block and can't drop, and the scheduled bit bounds the queue at #tasks — the bound lives elsewhere.” 7/18 executor drill 用。
