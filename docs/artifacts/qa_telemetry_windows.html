qa 圖解 · telemetry aggregation · Q5 認題:can't store them all / aggregate / windows

telemetry windows:換索引軸,亂序就蒸發

整機櫃數十億筆訊號,全存不可能——聚合進固定數量的 time window,記憶體 O(#windows) 與樣本數徹底脫鉤。這題的靈魂只有一句:把資料結構的索引軸從「第幾個到的」換成「樣本自己的時間屬於哪一格」。換完之後,「亂序怎麼辦」的答案是不辦——你根本沒在看到達順序。此頁停在概念層;三個實作邊界(7/24 的動手題)只點名、不給答案。

0 · 換索引軸:event time,不是 processing time

window_index = ts / W        // W = window 長度;整數除法
// 只看樣本自己的純函數:同一筆 ts,現在到、晚三秒到、跟五百筆擠著到,
// 算出來永遠是同一格。到達順序從頭到尾沒有出場。
ring buffer(彩排 a)time window(本題)
索引軸「第幾個到的」(processing time)「樣本自己屬於哪格」(event time)
亂序災難(順序即語意)無害(索引不看順序)
記憶體O(capacity)O(#windows),與樣本數、速率皆脫鉤
保留的東西原始值統計摘要(原始值蒸發)

1 · 格子裡不存樣本,只折四個數字

count += 1;  sum += v;  min = min(min, v);  max = max(max, v);  // 每筆 O(1)

亂序無害的代數理由:這四個運算可交換——先折 A 再折 B 等於先折 B 再折 A。兩個必被追問的點:

  • average 要存 sum + count,不能存 running average——兩個平均沒辦法合併。
  • min/max 只在 tumbling(固定)window 是 O(1)。sum 有反元素(離開時 sum -= v 還原),min/max 沒有——你不能「減掉」一個 min。固定 window 從不移除樣本(時間到就關格開新格),所以不需要反元素;sliding window 的 min/max 只能重掃或上 monotonic deque。這是代數結構問題,不是實作技巧問題。

3 · 什麼時候聚合才划算:每格樣本 ≫ 1

每 node 速率存原始值(覆蓋 60s)聚合(1s 格 × 60)
1 Hz4.3 MB ← 原始值贏8.6 MB
1 kHz4.3 GB8.6 MB
1 MHz4.3 TB8.6 MB

1 Hz 下每格只有 1 筆——你花 4 個數字記 1 筆,聚合是把資料變大的有損壓縮;crossover 在每格 ~2 筆。所以正確的說法不是「聚合比較省」,是「聚合的成本與速率無關」:

存原始值:memory = rate × T × size      // rate 在式子裡
聚合:    memory = (T / W) × 固定        // rate 不在式子裡

代價講清楚才叫 trade-off:聚合之後你永遠答不了「14:03:22 那筆讀數是多少」。切點是產品需求不是效能——儀表板只要統計 → 聚合;要看得到原始波形 → 退回 drop-oldest ring,把 rate × 保留秒數 × size 算給面試官,讓他決定付不付。

4 · 三個實作邊界——點名,不解答(7/24 的動手題)

只保留 N 格時,這三題就是彩排 f(aggregator 延伸)的全部難度,動手前先自己想:

  1. 新來的 window_index,住哪個 slot?(N 格循環重用——這格上一任住戶的資料呢?)
  2. ts 落在已淘汰的過去——用什麼判準認出「太老」?拒收要 O(1)。
  3. ts 跳到很遠的未來——中間被跳過的那些格,裡面的舊資料誰負責清?什麼時候清?

加一題 R1 同款陷阱當開胃菜:空 window 的 stats 為什麼必須回 None、不能回 zero 填充?提示:zero 對 count/sum 無害,對 min 是什麼?

5 · 面試句庫

“I index by event time, not arrival: window = ts / W is a pure function of the sample itself, so out-of-order arrival is a non-event — the four fold operations are commutative.” 換索引軸 + 可交換性,一句收掉亂序追問。
“Aggregation's real property isn't ‘smaller' — it's that memory is rate-independent: raw is rate × T × size, windows are T/W × constant. Below ~2 samples per bucket, raw actually wins — so Q2's rate number decides, not taste.” 划算判準講到位 = 展示你不是背口訣。
“The cost is irreversibility: after folding I can never answer ‘what was the reading at 14:03:22'. That's a product decision, so I'd ask whether the dashboard needs raw waveforms before choosing.” 代價 + 把球丟回需求——clarify 精神收尾。
