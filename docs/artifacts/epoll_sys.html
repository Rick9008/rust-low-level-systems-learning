epoll_sys

這裡沒有 libc crate。只有七個 unsafe extern "C" 宣告, 和一個 kernel 說了算的位元組佈局。整個模組的難度不在 epoll 的語意—— 在你和 kernel 之間那條沒有型別檢查的邊界:一個 u32 的位元、 一個 12 位元組的 struct、一個回傳 -1 的整數。

1 · 邊界長什麼樣子

Rust 對 kernel 一無所知。unsafe extern "C" 區塊做的事只有一件: 宣告一個承諾——「這個符號存在,它的參數與回傳值長這樣」。 編譯器不驗證,linker 只比對符號名。簽名抄錯一個型別,程式照樣編過、照樣連結, 然後在執行期把垃圾交給 kernel。

宣告C 原型(man page)回傳約定
epoll_create1 int epoll_create1(int flags) fd,或 -1 + errno(EMFILE / ENOMEM)
epoll_ctl int epoll_ctl(int, int, int, struct epoll_event *) 0,或 -1 + errno(EEXIST / ENOENT / EPERM)
epoll_wait int epoll_wait(int, struct epoll_event *, int, int) 就緒數(0 = timeout,不是錯誤),或 -1 + errno(EINTR)
close int close(int fd) 0 或 -1 + errno(EBADF)。絕不重試
eventfd int eventfd(unsigned int, int) fd,或 -1 + errno
read / write ssize_t read(int, void *, size_t) 位元組數,或 -1 + errno(EAGAIN)

C 沒有 Result。錯誤全部擠在同一個整數的「負數區」裡, 真正的原因放在另一個地方:errno,一個 thread-local。 C 的 errno 其實是巨集,展開成 *__errno_location()—— 每個執行緒一份。所以「讀 errno」這件事本身也是一次 FFI 呼叫。 本模組刻意不綁它:std::io::Error::last_os_error() 就是 std 已經綁好的同一條路。少一個 unsafe 面,少一次抄錯簽名的機會。

2 · events 是一個 u32,不是「一組選項」

EPOLLIN 不是一個常數的名字,它是第 0 個位元。 你交給 kernel 的 events 是一個 32 位元整數: | 是把位元點亮,& 是問「這一位亮著嗎」。 點開下面的旗標,看那個 u32 真正變成什麼。

三類旗標,語意完全不同,卻塞在同一個 u32 裡: IO 旗標(你要求、kernel 也回報)、 EPOLLERR / EPOLLHUP(你不能要求, kernel 一定回報——所以 events & EPOLLIN 之前必須先檢查它們, 否則你會對一條已經死掉的連線呼叫 read(),拿到 ECONNRESET 才發現)、 EPOLLET / EPOLLONESHOT(註冊用的修飾詞, kernel 回報時從不設它們——如果你在回傳的 events 裡看到 EPOLLET, 那不是 kernel 在跟你說話,是你讀錯記憶體了,理由見下一節)。

3 · 12 個位元組,不是 16

struct epoll_event 是一個 u32 後面接一個 u64。 自然對齊會在中間塞 4 個位元組的 padding,湊成 16。 但 x86_64 的 kernel ABI 上它是 __attribute__((packed))—— 12 個位元組,沒有洞(歷史包袱:為了讓 64-bit kernel 直接吃 32-bit 程序的結構)。 Rust 這邊必須 #[repr(C, packed)] 跟上, 否則你和 kernel 對同一塊記憶體的解讀會差 4 個位元組。

#[repr(C, packed)] 12 bytes  ·  kernel 說了算

#[repr(C)] 自然對齊 16 bytes  ·  多出 4 bytes 的洞

單看一個 struct,差 4 個位元組好像沒什麼。但 epoll_wait 是寫一整個陣列: kernel 以 12 為 stride 往下寫,你以 16 為 stride 往下讀。以下是 kernel 回報三個事件 (EPOLLIN, token=100) (EPOLLOUT, token=200) (EPOLLIN|EPOLLRDHUP, token=300) 時,忘了 packed 的 Rust 實際讀到的東西:

注意這裡沒有記憶體越界:kernel 只寫 12×N 個位元組,你的緩衝有 16×N。 沒有 segfault、沒有 ASan 報警,測試甚至可能會過——第一個事件的 events 是對的。 症狀是「token 偶爾亂掉」,而根因在 struct 宣告上,兩者距離極遠。 這就是為什麼 size_of::<EpollEvent>() == 12 值得被寫成一個測試: 把 ABI 契約釘在編譯的那一刻,而不是在生產環境的日誌裡追它。

packed 的代價:不能取欄位的參照。 &ev.data 是一個未對齊參照,是 UB,編譯器直接擋下(E0793)。 連 assert_eq!(ev.data, 7) 都會踩到——巨集內部會取參照。 正確做法是把整個值複製出來:let data = ev.data;, 或用 &raw const ev.data(舊寫法 addr_of!)拿裸指標再 read_unaligned。

EINTR 不是錯誤。signal 打斷 epoll_wait 時, 什麼事都沒發生:沒有事件、沒有損壞、沒有狀態改變。 把它上拋給 caller,等於逼每一個 caller 都寫一次 if err == EINTR { retry }。 所以 wrapper 在 loop 裡吞掉它: Err(e) if e.kind() == Interrupted => continue。 其他 errno 一律如實上拋——wrapper 的工作是消除假錯誤,不是隱藏真錯誤。

epoll_wait 回 0 也不是錯誤,是 timeout 到期。 < 0 才是。這個「負數即錯誤」的約定是 C 的世界觀, cvt() 這個十行函式的全部工作,就是把它翻譯成 io::Result—— 翻譯完之後,整份程式碼就再也不用看到 -1。

5 · 每個 unsafe 到底在斷言什麼

unsafe 不是「我要做危險的事」,而是「我向編譯器保證某件它無法驗證的事」。 保證的內容必須寫下來,否則三個月後沒有人知道破壞它會怎樣。

unsafe 區塊斷言了什麼破壞它會怎樣
epoll_create1(EPOLL_CLOEXEC) 沒有指標參數;flags 是合法常數 幾乎無法破壞——七個裡面最無害的一個
epoll_ctl(epfd, op, fd, &mut ev) ev 是活著的區域變數,指標在整個 syscall 期間有效; fd 的有效性由 caller 負責 傳懸空指標 → kernel 從你的 stack 讀垃圾;傳已經 close 的 fd → EBADF(這算走運)
epoll_wait(epfd, buf.as_mut_ptr(), buf.len(), t) buf 至少有 maxevents 個佈局正確的元素可寫 唯一能讓 kernel 幫你踩壞記憶體的地方。 maxevents 大於實際容量 → kernel 直接寫出界 → heap 損毀
close(self.epfd)(在 Drop 裡) epfd 由本結構獨佔,Drop 只跑一次,所以只 close 一次 double-close:那個 fd 號碼可能已經被 kernel 重新配給別的連線 → 你關掉了別人的 socket,而且不會有任何錯誤訊息
write(fd, &raw const one, 8) 指標指向恰好 8 個位元組的 u64(eventfd 的 ABI 要求) 少於 8 bytes → EINVAL;傳錯位址 → EFAULT

看第三列。安全 wrapper 的價值不在「包起來比較好看」, 而在 wait(&self, buf: &mut [EpollEvent]) 這個簽名裡, buf.len() 這個數字不可能說謊。 C 的介面允許你把 maxevents 和實際緩衝大小分開傳——那正是 bug 的產地。 slice 把兩者綁成同一個東西,整條 buffer overflow 的路徑就在型別層蒸發了。

EPOLL_CLOEXEC:一個旗標換掉一整類 bug

fork() 的子行程會繼承所有 fd;exec() 預設不會關掉它們。 所以一個沒有 CLOEXEC 的 epfd,會活在你 spawn 出去的每一個子行程裡: 子行程完全不知道自己握著它,但那個 fd 就是不會被釋放——而且它還讀得到。 在會 spawn 子行程的服務裡,這是 fd 洩漏與權限外洩的雙重來源。

正確答案不是「exec 之後記得關」:競態就發生在 fork 與 exec 之間, 多執行緒下你根本沒有那個空隙。正確答案是 在建立 fd 的那一刻就原子地標上 CLOEXEC。 這正是 epoll_create1(EPOLL_CLOEXEC)(而不是舊的 epoll_create)存在的理由, 也是 EFD_CLOEXEC、SOCK_CLOEXEC、O_CLOEXEC 這一整排旗標存在的理由。

Drop:fd 的生命週期是型別的一部分

Epoll 這個 struct 裡只有一個 RawFd,但它做到兩件 C 做不到的事: 忘記 close 不可能發生(Drop 一定跑), close 兩次也不可能發生(Epoll 不是 Copy,move 掉就沒了)。 而在上面那個 stepper 裡你會發現:還沒拿到 epfd 之前,ADD 是按不下去的。 在 Rust 這一層,「對一個還沒建立的 epoll 呼叫 epoll_ctl」這個錯誤根本無法被表達, 因為 Epoll::add(&self) 需要一個已經存在的 Epoll。 RAII 把一個執行期的 EBADF,變成了一個編譯期的型別錯誤。
