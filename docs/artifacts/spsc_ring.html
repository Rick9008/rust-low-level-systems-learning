spsc_ring

一個 producer、一個 consumer、兩個只增不減的計數器。沒有 CAS,沒有鎖。 整個模組的難度不在資料結構——在兩個計數器之間那條看不見的 happens-before 邊。

1 · 環是怎麼轉的

head 與 tail 是自由跑計數器:只增,永不 wrap 回 0。 tail − head 直接就是元素數,所以滿/空判定不必浪費一格。 實體槽位是 counter & mask——這是容量必須為 2 的冪的原因, 等一下用「溢位」按鈕就看得到為什麼。

head0
tail0
tail − head0
cap4
mask0b11
stateempty

按到滿:tail − head == cap,push 回 Err(item) 把值歸還給呼叫端 ——backpressure 是 caller 的事,不是 ring 的事(spin、park、丟棄,ring 不替你決定)。 按「跳到溢位點」再連按 push:計數器從 usize::MAX wrap 到 0, 但 & mask 的槽位序列依然連續。cap=3 的話這裡會跳格—— 那是正確性 bug,不是效能問題。

2 · 那條看不見的邊

上面的動畫有個謊言:它假設 producer 寫進槽位的值,consumer 一定看得到。 在 C11 記憶體模型裡,這件事需要被證明,而證明它的東西叫 release/acquire。 把開關切到 Relaxed,看同一組操作會發生什麼。

producer

slot[0].write(42)
tail.store(1, Release)
happens
before

consumer

tail.load(Acquire) → 1
slot[0].read()
結果 consumer 讀到 42。producer 對槽位的寫入 happens-before tail 的 Release store; consumer 的 Acquire load 讀到那個 tail,就繼承了整條因果鏈。值必然完整可見。

Relaxed 版在 x86 上跑一億次也不會錯——x86 是 TSO,硬體不重排 store-store、load-load, Relaxed 編出來跟 Release 是同一條 mov。 bug 在原始碼裡,不在你的 CPU 上。這正是為什麼這個模組必須用 loom 驗,不能用壓力測試驗。

3 · 每一個 ordering 都有名字

六個記憶體操作,沒有一個是「保險起見設強一點」。每個 Relaxed 都因為 單一寫者而合法,每個 Acquire 都對應一個具體的 Release。

操作ordering配對與理由
producer 讀自己的 tailRelaxed單一寫者讀自己寫的值,無需同步
producer 讀 headAcquire配 consumer 的 head Release:確認槽位已被讀完,才敢覆寫
producer 寫槽位 → store tailRelease槽位寫入 happens-before tail 發布;讀到新 tail 的人必看到完整元素
consumer 讀自己的 headRelaxed同上,單一寫者
consumer 讀 tailAcquire配 producer 的 tail Release
consumer 讀槽位 → store headRelease讀取 happens-before head 發布;producer 才能安全覆寫

4 · loom 抓得到,壓力測試抓不到

把上表任何一個 Release/Acquire 降級成 Relaxed,然後用兩種方式驗證。 這是 cargo run -p reference --example loom_vs_stress 在真實機器上跑出來的數字:

驗證方式規模結果
真 OS thread 壓力測試 2,000,000 次 push/pop 通過 — 0 個異常(486ms)。debug 與 release 皆然
loom(同一份原始碼) 2 thread / cap 1 / 2 元素 Causality violation — 379µs
loom(正確版) 同上 通過(6.6ms)

壓力測試「通過」是紅字,loom「失敗」是綠字——因為前者代表 bug 溜掉了,後者代表 bug 被抓住了。 loom 不是跑很多次,是在 C11 模型上窮舉:它的 atomic 存的是一整段寫入歷史 + 因果圖, Relaxed load 時會依規則真的把過期的值回給你。

5 · false sharing:兩個無關的變數在硬體層互踢

head 只有 consumer 寫,tail 只有 producer 寫——邏輯上毫無關係。 但若它們落在同一條 64 位元組 cache line,producer 每次 store tail, MESI 就把 consumer 核心上那條 line 打成 Invalid;consumer 讀 head 就 miss。 兩核互相把對方的 cache 打掉,吞吐掉一個數量級。

#[repr(align(64))] 讓兩個計數器各佔一條 line。 代價約 112 位元組——用空間換掉 cache coherence 流量。這是這個模組唯一「為了硬體」而做的設計, 其餘全部是為了記憶體模型。
