同一條 ring,五種睡法

SPSC ring 本身不帶通知——「沒貨時誰睡、誰叫醒」是一個獨立插槽。 這頁做三件事:比較五種睡法(含「沒有 epoll 是不是只能 sleep」的答案)、 親手走一遍掛牌握手壞掉的交錯(拔掉 fence,consumer 帶著貨睡死 ——x86 上真的會發生),以及多源扇入為什麼是 per-source SPSC 不是 MPSC。

① 等待策略階梯——「按事件醒」vs「按時間醒」

先分兩種睡:按事件醒 = kernel 幫你睡,事情發生時提早叫醒 (blocking read、condvar、park、epoll);按時間醒 = sleep,時間到才醒,事件來了也叫不動你。 沒有 epoll ≠ 用 sleep:sleep 只在「多路 × 無多路原語 × 不開多 thread」三個條件 同時成立時出場,而且它買的是「別燒死 CPU」,不是「等到事件」。

② 掛牌握手:拔掉那道 fence,看它睡死

spin 額度用完後,consumer 想睡。producer 每筆 unpark = 每筆一次 syscall, 所以改成:consumer 掛牌才睡、producer 看到牌才 unpark。 但「掛牌 → 再查佇列」與「push → 查牌」是教科書 store-buffering:兩邊都先寫後讀, 寫還躺在各自的 store buffer 裡,讀就從旁邊繞過去了。 StoreLoad 重排是 x86-TSO 唯一允許的重排——這個 bug 在你筆電上就會發生。

③ 扇入:多源就 per-source SPSC,不是 MPSC

source_0 thread ──SPSC ring_0──┐
source_1 thread ──SPSC ring_1──┼──▶ consumer(round-robin 掃,每輪每條最多 B 筆)
source_2 thread ──SPSC ring_2──┘

每源一條自己的 ring:每條仍是單寫者(零 CAS)、某源爆量只塞滿自己的 ring、 per-source FIFO 保住(跨源全域順序沒有——說出口,這是 clarify 的料)。 按下爆源,看隔離發生:

公平性:bounded batch(每輪每條最多 B 筆)——熱源不能餓死其他源。 scale:source 靜態分片給多條 consumer;work-stealing 同時破壞單寫者與 per-source FIFO,不選。拓撲每一步都在守單寫者。 另外:SPSC 上做不到 drop-oldest(head 是 consumer 單寫的)——SPSC-safe 的 是 drop-newest + 計數;要「新蓋舊」換 per-key conflation slot。
