DS 同步三檔:Mutex 就夠、值得無鎖、無鎖不存在

同一個資料結構,多執行緒要共享時你有三檔:上鎖(整組機關塌縮)、無鎖(付語意稅買 progress 保證)、或承認無鎖版根本不存在(精確 LRU)。這頁把 repo 裡的配對組串成一堂選型課:塌縮定理、老實的成本帳、鎖階梯、以及「什麼結構值得無鎖」的判準——面試被問 “how would you make X thread-safe” 時,答案的骨架就是這張圖。

2 · 老實帳:Mutex vs lock-free,誰快?

情境Mutexlock-free
無競爭futex fast path:一個 CAS 進、一個 store 出單發 CAS——幾乎同價
高競爭等待者去睡:不燒 CPU、不 ping-pong cache lineCAS 重試風暴,可能更慢
持有者被 preempt全員卡住等它醒別人仍有進展(lock-free 的定義)
複合操作同臨界區天生原子(alloc + 寫值)只有單字原子性,靠所有權轉移協議拼
tail latency / priority inversion有暴露可控 / 免疫
“Uncontended, a mutex is one CAS — same price as lock-free. What lock-free buys is progress guarantees: no priority inversion, and if a thread gets preempted mid-operation, everyone else still makes progress. It's about latency and liveness, not throughput.” 被問「lock-free 比較快嗎」的標準開場——先否定前提。

4 · 互動:lock-free DSU 的兩種 CAS——一個承載正確性、一個只是 hint

dsu_lockfree 丟掉 union-by-rank(兩處寫,單 CAS 做不到),換固定隨機 priority:link 塌縮成一個字的 CAS,而 expected value 就是「root 的定義」本身(parent[lo] == lo)。切換兩個劇本:

    return true;   // 失敗則整段重來:重新 find(有人成功了,世界變了)

// find 裡的 path halving:CAS 失敗「不重試」——它只是效能 hint
let _ = self.parent[x].compare_exchange(p, gp, Release, Relaxed);

同一支演算法裡的兩個 CAS,失敗處置完全相反——判準只有一條:這個寫入承載不變量(連通性),還是只是加速 hint(壓縮)?前者失敗必須重來,後者失敗直接走人。

5 · 為什麼 DSU 免 generation tag,arena 卻必須掛?

arena_lockfree(要 gen)dsu_lockfree(免 gen)
expected valuehead == (gen, idx)parent[lo] == lo(root 自指)
舊值會回來嗎會:idx pop → free → 再 push,同一索引帶不同 next 回到 head永不:root 資格一去不返(parent 單調向根)
結論CAS 只比 idx 會誤成功 → 掛 gen 讓舊讀者必敗expected 失效即永久失效,ABA 無從發生

一句話講穿 ABA:問題從來不是「CAS 比對值」,是「expected value 會不會失而復得」。單調性(一去不返)是最便宜的 ABA 免疫。

6 · LRU:無鎖版為什麼不存在

第一個殘酷事實:精確 LRU 的 get 是寫操作——promote-to-MRU 要動雙向鏈表。這直接判了 RwLock 死刑:你以為 cache 讀多寫少是 RwLock 完美場景,結果每次讀都要寫鎖。而真無鎖化要在同一個熱點(list head)上做多指標原子改 + 逐出節點的記憶體回收——成本 > 價值,整個工業界都繞道:

  • sharding(lru_locked):hash 選 shard、每 shard 一把鎖一個 LRU。代價是逐出品質變 per-shard 近似:2 個 shard 各 cap 1,兩個 key 撞同一 shard——全域容量還有空位,照樣逐出。容量是靜態切分的,熱 shard 借不到冷 shard 的額度。
  • 放棄精確,recency 降級成 per-entry atomic:CLOCK(get 只做一個 Relaxed store,OS page cache 的做法)、Redis 抽樣 timestamp、W-TinyLFU(moka/caffeine:per-thread buffer 批次 replay)。讀路徑零鎖,換近似逐出。
“Exact LRU makes every read a write — the promote touches the list — so RwLock buys nothing. Production either shards it, accepting per-shard eviction, or downgrades recency to a per-entry atomic like CLOCK. Nobody ships a lock-free exact LRU; the cost of exactness exceeds its value.” 「LRU 怎麼 thread-safe」的完整答案,25 秒。

7 · 語意稅:無鎖化之後,回傳值的含義變了

  • connected(a,b) == false:「曾有一瞬間不連通」——回傳途中可能已被 union。線性化靠複查 parent[rx]==rx(root 資格單向消失,撐起整段區間)。
  • components() / sharded len():Relaxed 統計計數 / 行進中快照——不能當同步旗標。
  • 單操作可線性化,操作的組合不原子:兩次查詢之間世界可以整個換掉,呼叫端要自己帶外部同步。

8 · 自測:四題預測題(先想再翻)

1 · DSU:halving 的 CAS 失敗可以不管,link 的 CAS 失敗必須整段重來——為什麼?

兩個 CAS 守的東西不同。link 承載連通性不變量:失敗代表 lo 已不是根(expected 永久失效),硬寫會把樹接錯——必須重新 find 再試。halving 只是效能 hint:失敗代表別人已把 parent[x] 推得更遠(單調向根),此刻的結構比你想寫的還好,棄之即可;gp 仍在祖先鏈上,繼續爬完全正確。

2 · CLOCK 把 LRU 的 get 降成一個 Relaxed store——為什麼 Relaxed 不會出正確性問題?

因為那個 flag 不承載任何正確性,只是逐出品質的 hint。讀者丟失/晚到一個 flag,最壞結果是「某個最近用過的 entry 被提早逐出」——cache 語意本來就允許任意逐出(miss 只是變慢,不是錯)。沒有任何不變量掛在這個 store 的可見性順序上,所以不需要 happens-before,Relaxed 剛好。跟 DSU 的 halving 是同一根脊椎:hint 寫入不需要 ordering 保證。

3 · arena 的 lock-free pop:如果把 free_slot(idx) 挪到讀值之前(先還槽、再讀),會發生什麼?

還槽的瞬間,另一執行緒就能 alloc 到同一個槽並開始寫入新值——你的 assume_init_read 跟它的寫入形成 data race(UB),讀到撕裂值。free_slot 的 Release-CAS 是「我讀完了」的發佈點:它必須排在讀之後,下一任的 Acquire 才能保證看到槽位已交還。Mutex 版三件事隨便排——因為整段在同一臨界區裡,沒有「別人」。

4 · sharded LRU 在什麼 workload 下逐出品質明顯劣化?

熱度跨 shard 不均時:熱 key 集中撞進同一 shard(hash 不均、或 key 天然聚簇),該 shard 反覆逐出還很熱的資料,而冷 shard 大片空著——容量靜態切分,借不過去。極端例:N-1 個 shard 全空,一個 shard 承受全部流量,等效容量從 cap 掉到 cap/N。這就是 §6 的「全域有空位照樣逐出」放大成 workload 級的樣子。

9 · 面試句庫

“My ladder is: one mutex first — correctness before cleverness. If contention shows up, shard by key. If the structure is a long chain with scattered access, hand-over-hand locking. Lock-free is the last rung, and only for structures whose writes are monotonic — like union-find, where a root never comes back, so CAS needs no ABA tag.” 選型題的 30 秒骨架:階梯 + 判準,一次講完。
“Union-find is unusually lock-free-friendly: parent pointers only ever move toward a root, so a stale CAS expectation fails permanently instead of being spoofed — no ABA, no generation tag. The price is semantic: connected-false is a snapshot, and I drop rank for randomized linking because rank needs a two-word atomic update.” dsu_lockfree 的一分鐘版本。
