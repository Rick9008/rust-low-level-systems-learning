Lock-free 的 P/C 階梯:SPSC → MPSC → Vyukov MPMC → SPMC

帶鎖時 P/C 數量無所謂(Mutex 吞掉一切,bounded_queue 天生 MPMC);拿掉鎖,分類法才長出牙齒:難度隨「每個變數有幾個寫者」爬升。這頁把整條階梯走一遍,主菜是 Vyukov bounded MPMC queue(crossbeam ArrayQueue 的骨架)——而它的核心零件,正是你在覆寫 ring 那頁學過的 per-slot sequence number,換了第三種用途。

0 · 階梯總覽:寫者數 = 難度

形狀誰在搶什麼同步成本代表作
SPSC每個 index 恰好 1 個寫者——沒人搶零 CAS,兩對 Release/Acquirespsc_ring(repo 主線)

1 · SPSC → MPSC:第一個 CAS 從哪裡長出來

SPSC 的全部魔法是「tail 只有我寫」。第二個 producer 一出現,兩個人同時 tail.store(t+1) 就會搶同一格——所以 claim 必須變成 CAS:

loop {
    let t = tail.load(Relaxed);
    // 誰 CAS 成功,slot t 就是誰的(獨佔),失敗者重試
    if tail.compare_exchange(t, t + 1, Relaxed, Relaxed).is_ok() { break t; }
}
// 拿到 slot t 之後才寫 payload……但新問題來了:

新問題:認領順序 ≠ 完工順序。producer A 認領 slot 5、producer B 認領 slot 6;B 先寫完。consumer 看 tail 已經推到 7,但 slot 5 還是半成品——consumer 不能再用「tail 推到哪就讀到哪」判斷可讀性,必須看每格自己的「寫完了沒」。這就是 per-slot 標記誕生的理由——把它做到極致,就是下一節的 Vyukov。

2 · 主菜:Vyukov bounded MPMC queue

設計一句話:每格掛一個 seq,數值編碼「這格現在處於第幾圈的哪個階段」;兩端的執行緒不跟對方溝通,只跟格子驗票。初始化:slot[i].seq = i。

// enqueue(多 producer 安全)
loop {
    let t = tail.load(Relaxed);
    let slot = &slots[t & mask];
    let s = slot.seq.load(Acquire);
    if s == t {                              // 這格正等著第 t 號寫入者
        if tail.compare_exchange_weak(t, t+1, Relaxed, Relaxed).is_ok() {
            unsafe { slot.data.write(item); }
            slot.seq.store(t + 1, Release);  // 蓋章:寫好了,等讀者
            return Ok(());
        }                                    // CAS 輸了 → 重試
    } else if s < t { return Err(item); }    // 落後一圈沒人讀 → 滿
    // s > t:別人搶先推進了 → 重讀 tail 再來
}

// dequeue(多 consumer 安全)——完全對稱
loop {
    let h = head.load(Relaxed);
    let slot = &slots[h & mask];
    let s = slot.seq.load(Acquire);
    if s == h + 1 {                          // 這格有第 h 號讀者要的貨
        if head.compare_exchange_weak(h, h+1, Relaxed, Relaxed).is_ok() {
            let item = unsafe { slot.data.read() };
            slot.seq.store(h + cap, Release); // 蓋章:騰空,等下一圈的寫入者
            return Some(item);
        }
    } else if s < h + 1 { return None; }     // 空
}

四個值得口述的性質:

  • 沒有回收問題:記憶體固定、slot 原地重用——這是它比 Michael–Scott 幸福的根本原因(對照 qa_unbounded_lockfree 的沼澤)。bounded 在 lock-free 世界不是限制,是解藥。
  • 序號同時解掉 ABA:slot 每圈 +cap,舊圈的認領者永遠對不上號。
  • lock-free 但不是 wait-free:CAS 輸了要重試;高競爭下兩端各自變成 CAS 熱點(cache line 搶奪)——所以吞吐夠不上 per-producer SPSC shard,這正是 playbook Q3「數千 producer → per-producer SPSC」那格存在的理由。
  • 一格三用的序號:撕裂偵測(seqlock)→ 套圈計數(覆寫 ring)→ 旋轉門(Vyukov)。同一顆螺絲,三種鎖法。

3 · MPSC 的另一條路:交換指標(認臉即可)

陣列式之外,MPSC 還有一支鏈式流派(Vyukov 的 intrusive MPSC,tokio 內部用它):producer 用一次 swap(XCHG)把自己掛上鏈尾——swap 必成功,不用重試迴圈,所以生產端是 wait-free;代價是 consumer 端偶爾要處理「鏈結還沒接好」的瞬間。認臉重點:「多寫者用 swap 代替 CAS 迴圈」是一個獨立的招,面試提一句就夠。

4 · SPMC:先問語意,它其實是兩題

語意每筆給幾個人正解
工作分發(N 個 worker 搶活)恰好 1 人沒人做 lock-free SPMC queue——直接用帶鎖 MPMC(thread_pool),或 per-worker deque + work-stealing:owner 在自己的 bottom 端免 CAS 推拉,小偷在 top 端 CAS 竊取(Chase–Lev,escalation ladder 第 4 階那個名字)
廣播(每人都要看到每筆)N 人這不是 queue,是 multicast:一個 ring,每個 consumer 自己的 cursor,producer gate 在最慢 cursor 上——Disruptor 的招牌用法(一份行情,journal / replicate / strategy 各自進度);退化成「只要最新值」= conflation slot / seqlock

所以「SPMC 有沒有教材」的正確答案是:先問你要分發還是廣播——問出來之後,兩條路的教材你都已經有了(thread_pool / qa_overwrite_ring)。

5 · 面試句庫

“Lock-free difficulty scales with writers per variable. SPSC needs zero CAS — every index has exactly one writer. MPSC puts a CAS on tail, and now claim order ≠ completion order, so each slot needs a ready flag. MPMC generalizes that flag into a per-slot sequence that acts as a turnstile — that's Vyukov's queue, crossbeam's ArrayQueue.” 整條階梯一段講完,每一步都說出「多了什麼、為什麼」。
“Bounded is the cure in lock-free land: fixed slots mean no reclamation problem, and the sequence number kills ABA for free. The swamp only opens when you go unbounded.” 把 qa_unbounded_lockfree 和本頁縫成一句。
“std ships mpsc; mpmc is still unstable — so on the pad it's Mutex<VecDeque> for MPMC, or I name crossbeam and move on.” p2 記過的小考點,一句收掉。
