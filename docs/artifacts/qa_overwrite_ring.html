覆寫也能 lock-free:seqlock ring 與 Disruptor

「滿時擠掉最舊」讓 producer 碰到 consumer 的 index,單寫者不變量破功——所以 push_overwrite 走不了 spsc_ring 的老路。但 drop-oldest 本來就放棄了無損,這打開另一扇門:producer 根本不看 consumer、無條件覆寫;由 consumer 用序號自己偵測「我讀到的東西被改過/被套圈了」。這一族就是 seqlock ring(perf ring buffer、行情 conflation),Disruptor 是同骨架的無損表親。

0 · 為什麼原做法 lock-free 不了(30 秒複習)

  • pop_front + push_back 的覆寫 = producer 去動 head → head 變雙寫者,spsc 的地基(每個 index 恰好一個寫者)塌了。
  • 更狠的:滿的時候寫入格 wrap(head+len) == head——producer 要覆寫的正是 consumer 下一個要讀的格,一寫一讀同一塊 payload = data race。

結論:別讓 producer 替 consumer 收拾。覆寫責任留在 producer(它只寫自己的東西),偵測責任交給 consumer。四個願望(lock-free / producer 不阻塞 / 覆寫最舊 / 無損 FIFO)本來就不能全拿——drop-oldest 早已交出「無損」,剛好用它換。

1 · 零件:每格掛一個 sequence number

結構長這樣——注意 producer 需要的東西全是自己寫的:

struct Slot<T> {
    seq:  AtomicU64,          // 這格的「版本號」,只有 producer 寫
    data: UnsafeCell<T>,      // payload;T 必須是 POD(Copy、無指標無 Drop,原因見 §2)
}
struct Ring<T> {
    slots: Box<[Slot<T>]>,    // cap = 2 的冪
    tail:  AtomicU64,         // producer 的自由跑計數器(單寫者,同 spsc)
}                             // 沒有 head!consumer 的進度是 consumer 自己的私事

Producer 寫入(永不阻塞、永不讀對方),經典 seqlock 的奇偶協議:

let t = tail.load(Relaxed);              // 讀自己的計數器
let slot = &slots[(t & mask) as usize];
slot.seq.store(2*t + 1, Release);        // ① 奇數 = 「施工中」
unsafe { *slot.data.get() = item; }      // ② 寫 payload
slot.seq.store(2*t + 2, Release);        // ③ 偶數 = 完工,版本 = 輪次
tail.store(t + 1, Release);

序號一石二鳥:奇偶位說「現在有沒有人在寫」,數值本身說「這格被寫到第幾輪了」——後者就是 §3 套圈偵測的鑰匙。

2 · Consumer 的讀協議:先拿,再驗票

兩個由此而來的硬限制,面試必講:

  • T 必須是 POD(Copy、無指標、無 Drop):驗票失敗的那份 copy 是撕裂值,你「拿了但不能用」——若 T 裡有指標,連 copy 這個動作本身都可能爆。telemetry 的小記錄(10 B 那種)剛好完美符合。
  • 讀是投機的(optimistic):寫得太頻繁時讀者可能連續驗票失敗——seqlock 買「寫者永不等」,賣「讀者可能重試」。方向跟 Mutex 剛好相反,跟 RwLock 更是相反(那是讀者擋寫者)。

深水區標註(誠實聲明):在 C++/Rust 記憶體模型下,「copy 一塊正被寫的 non-atomic 記憶體」嚴格說是 data race——生產級實作用 per-word atomic/volatile read 迴避,學界叫 atomic memcpy 問題。面試講到協議層(上圖)即可,這個泥潭點名字就好。

3 · 套圈(lapping):consumer 落後一整圈怎麼辦

4 · 認臉:這一族住著誰

名字一句話跟本頁骨架的關係
Linux perf / ftrace ring buffer(overwrite mode)kernel 的觀測資料環:producer(kernel)永不阻塞,tracer 落後就被套圈本頁的教科書本尊
Conflation slot(行情「只要最新價」)每個 key 一格,新價無條件蓋舊價,讀者拿到的永遠是最新單格版的 seqlock ring——卡 3 market data 的 canonical,`signal_pipeline` 的 drop-newest vs conflation 節
LMAX Disruptor金融業招牌:ring + per-slot published sequence + 等待策略可插拔同骨架的無損表親:producer 不套圈,改為 gate 在最慢 consumer 的進度上(等它)——把「覆寫」換回「backpressure」,其餘零件幾乎同款
經典 seqlock(kernel 的 jiffies/時間戳)單一共享值的無鎖讀:讀者驗版本號重試把 ring 縮成一格、去掉輪次,就是它——本頁協議的祖形

一個漂亮的對比要點:這一族沒有回收問題——slot 原地重用、記憶體固定,`qa_unbounded_lockfree` 那頁的沼澤(何時能 free)根本不存在;代價換成了撕裂與套圈,而兩者都由序號一個零件解決。固定記憶體 + 序號 vs 動態節點 + 回收,是 lock-free 兩大家族的分水嶺。

6 · 面試句庫

“Drop-oldest already gives up losslessness, so lock-free overwrite is legal — just not the way you'd first try. The producer never looks at the consumer: each slot carries a sequence number; the reader copies, then validates the sequence before and after — if it changed, the read is torn and discarded; if it jumped a whole lap, I've been overtaken, so I skip forward and count what I lost.” 核心協議一段講完:序號 = 撕裂偵測 + 套圈計數,一個零件兩份工。
“That's the perf-ring-buffer / seqlock family. LMAX Disruptor is the lossless cousin — same per-slot sequences, but the producer gates on the slowest consumer instead of lapping it.” 認臉句:一句話把兩個名字放進正確的位置。
“In 45 minutes I ship the mutex version — the seqlock ring is the upgrade path, and it only pays when someone is buying producer-side p99.9.” 收尾:光譜心法不變,停在需求要的那站。
